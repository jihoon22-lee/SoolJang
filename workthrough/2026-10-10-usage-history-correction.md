# 실사용 흐름 WP05 — 시음 찾기·안전한 정정

- 기준 main `23d5c89`(WP04 #164 통합), `feature/usage-history-correction`.
  R09/R10/R11, S04/S08/S10/S11/S15~S20의 WP05 범위다. 아래는 미커밋 변경의 실행 기록이다.
- 제품·규격·병·기간을 같은 시음에 적용하는 커서 페이지·요약과 단건 조회를 추가했다.
  기존 배열·병별 페이지의 계약은 유지하고 제품 판본·용량·구매·현재 병 상태를 덧붙인다.
  오프라인은 기기에 저장된 같은 범위의 자료를 표시하고 서버 요약과 섞지 않는다.
- 시음 내용·양·대상 정정은 시음·첨부 ID를 유지한다. 기본은 현재 상태/잔량 유지이며,
  명시적 최종 상태를 선택하면 원래 병과 대상 병을 함께 검증·적용한다.
- 구매 SKU 정정은 같은 제품의 목표 규격을 사용한다. 삭제된 병·연결 시음도 포함한
  정확한 ID/버전 집합을 검증하며 다른 구매·병 없는 시음은 바꾸지 않는다.
  새 용량보다 큰 잔량은 자동 절삭하지 않고 사용자가 최종값을 지정한다.
- 기존 receipt·revision·record event를 재사용한다. 필드 생략과 명시적 null을 구분하는
  요청 hash와 전체 응답을 같은
  트랜잭션에서 저장하고 만료 receipt를 재실행하지 않는다. 권한 확대·신규 migration은 없다.
  관련 병 revision은 기록만 정정해도 증가해 오래된 실행 취소를 막는다.
  생략/null 구분과 JSON 키 순서 재시도까지 포함한 정정·동시성 25개가 통과했다.
- 날짜/대상 변경 또는 최종 상태 변경은 대상 병의 알려진 개봉일≤시음일≤종료일을 검증한다.
  기존 미래일 허용·날짜 미기록과 내용만 수정하는 legacy 날짜 불일치는 유지한다.
- 현재 초안과 확인한 버전을 보존한다. 네트워크·5xx·408 결과 불명은 같은 요청으로 확인하고
  409는 최신 상태를 명시적으로 재확인한다. 계정 전환·사용자 탐색 이후 늦은 응답은 무시한다.
  과거 receipt 응답을 Dexie에 덮지 않고 최신 GET/pull을 기다리며 재확인·전체 보기 경로를 제공한다.

## 실제 검증과 보완

- 백엔드 집중: 정정·동시성 22개, 시음 조회 경합을 더한 관련 66개 통과.
  두 로그인 세션, 동일 요청 재전송, 원본/목표 변경, 소유권, 첨부, 삭제 자식,
  모든 병 상태, 만료 receipt, 오래된 취소, 영향 밖 구매 보존을 포함한다.
- 조회 중 다른 세션이 병·부모·시음을 삭제하면 `KeyError/500`이 나던 경합을 재현했다.
  시음과 맥락을 한 JOIN snapshot으로 다시 읽고 필터를 재적용한다. 단건은 404,
  페이지는 사라진 행을 빼되 최초 cursor로 계속 진행한다. 이 경계 17개가 통과했다.
- 웹 정정·조회·공통 보호·탐색 집중 62개 통과. 저장 중 pull이 URL 연결을 먼저 바꿔도
  폼을 보존하고, browser hash 이동 후 늦은 성공은 새 맥락을 바꾸지 않는 회귀 4개를 포함한다.
- 구매 분할로 다른 구매로 이동한 병의 최종 상태 초안은 숨기지 않고 명시적으로 해제한다.
  동일 SKU의 영향 밖 시음 대기는 막지 않으며, 로컬 조회는 모든 부모/자식의 소유권을 검사한다.
- 구매 정정 직후 잔량 편집기에 이전 용량이 남는 문제를 고쳤다. 같은 병 ID의 구매/SKU
  변경을 구독해 상한을 갱신하고 작성 중 입력은 유지한다. 관련 64개 회귀 통과.
- 열린 전체 시음 이력이 같은 화면의 새 기록을 자동 반영하지 않던 점을 보완했다.
  sync cursor 변경 후 서버 시음 조회·요약을 갱신한다. 조회/탐색 집중 14개 통과.
- 최종 `npm --prefix web run check`: **939 passed / 90 files**, branch **82.66%**.
  format/lint/typecheck/build 통과. 실제 offline과 standalone 최신 SKU 확인의 담당 33개
  회귀도 포함한다. 로그는 `/tmp/usage-wp05-web-final-all.log`다.
- `onlineManager.setOnline(false)`에서 local GET이 대기 상태로 멈추는 두 회귀를 재현하고
  로컬 조회만 `networkMode=always`로 고쳤다. 실제 offline에서도 50건 밖 기록과 초안을 읽는다.
  병 없는 시음은 목표 제품/SKU를 서버에서 다시 읽고 변경된 용량·판본을 명시적으로 확인한다.
- 최초 Python 전체 검사는 1,554 passed / 2 failed / 30 skipped였다. 실패 2개는 새 응답의
  현재 구매·병 맥락까지 생성 시점과 동일하다고 비교하던 기존 회귀였다. 시음 원본 보존과
  현재 맥락 갱신을 나눠 검사하도록 보완했으며 해당 7개가 통과했다.
- 최종 `.venv/bin/pytest -q`: **1,559 passed / 30 opt-in skipped**, 커버리지 **92.11%**.
  `SOOLJANG_ENV_FILE=`, `SOOLJANG_ENVIRONMENT=test`,
  `SOOLJANG_DATABASE_URL=postgresql+psycopg://sooljang@127.0.0.1:54329/sooljang_test`를 명시했다.
  최종 로그는 `/tmp/usage-wp05-backend-final-checked.log`다. 실데이터·성능·복구 opt-in은 미실행이다.
- Ruff·format(319 files)·ty·secret scan·diff check 통과. 원격 CI는 대기 중이다.

## 실브라우저 진행

Chromium, API 8212/웹 5176, 별도 합성 DB. 제품·SKU·구매·시음·정정은 실제 UI로 수행했다.
첨부 보존 확인용 합성 1px PNG 한 개만 기존 시음 업로더 UI가 없어 인증 API로 준비했다.
운영 데이터·유료/외부 호출·시계 가속·강제 클릭은 사용하지 않았다.

- UI로 500/750ml와 같은 이름의 2020/2021 판본, 최초 50ml 시음을 만들었다.
- G09: 시음 A→B 이동 후 A500/B700ml, 같은 시음/첨부 ID와 B의 SKU를 확인했다.
- 다른 빈티지로 기록만 이동할 때 원래 700ml와 목표 미개봉 전량을 유지했다.
  다시 원래 병으로 옮겨 양을 25ml로 고쳐도 현재 잔량은 바꾸지 않았다.
- 개봉·시음이 있는 구매를 500→750ml로 정정해 ID·첨부·다른 구매의 병을 보존했다.
  잔량 650ml에서 750→500ml 축소는 저장을 막고 명시한 450ml로만 적용했다.
- 다른 탭에서 1ml를 기록한 뒤 오래된 정정은 409. 초안 보존과 최신 상태 재확인 후 저장을
  확인했고 잔량 449ml를 보존했다.
- 추가 51개 시음을 UI로 입력해 총 53개를 만들었다. 첫 50개＋선택 기록 1개를 표시하고,
  더 보기로 53개를 중복 없이 읽었다. 기간 조건 1개＋선택 기록 1개는 실제 offline에서도 유지된다.
- 360/390/768/1440px 정정 화면은 각 viewport와 scrollWidth가 같았다. 360px 최종 상태
  입력 화면을 직접 살펴봤으며 병별 맥락·잔량과 저장 버튼을 확인했다.
- 병 연결을 해제해 2021 규격의 시음으로 이동한 뒤 원래 병으로 다시 연결했다.
  잔량 449ml, 같은 시음·첨부 ID를 확인했다. 최종 재검증의 pageErrors는 0건이다.

초기 선택자의 접근성 이름 문제를 확인하며 select/textarea의 이름을 고정하고 메모 폭을
늘렸다. 현재 증거는 `/tmp/sooljang-usage/wp05-browser-artifacts/`의
`select-labels/report.json`(앞 2개), `accessible-labels/report.json`(후속 4개),
`final/report.json`(50건 밖/실제 offline·4개 폭·standalone 3개 통과)에 있다.
브라우저 흐름은 앞 2개＋후속 4개＋최종 3개의 서로 다른 항목으로 구분하며 전체 PWA S01~S20
수용으로 합산하지 않는다. 실패한 스크립트 결과도 덮지 않고 보존했다.
