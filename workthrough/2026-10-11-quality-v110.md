## D. 백업·격리 복원과 운영 경계

태그 전 운영 백업을 생성했고 체크섬·첨부 참조·키·덤프 목차 검사를 통과했다. 별도 격리 DB와
uploads에 실제 복원한 뒤 schema 0020→0021 upgrade 및 drift 검사를 수행했다.
추가 두 열을 제외한 **43개 테이블의 기존 행 수·내용 해시가 이전 전후와 앱 조회 후 모두 일치**했다.
원본 ID·암호문을 포함한 기존 내용을 비교했으며 개별 기록·해시·키·백업 내용은 이 문서에 싣지 않는다.

worker를 끈 격리 복원 앱에서 인증된 읽기 19검사를 통과했다. 로그인 검증에 필요한 격리 변경은
rollback하여 보존 대조를 마쳤다. 백업 manifest의 운영 첨부 파일은 0건이므로 대표 운영 첨부
열람은 대상 없음이다. 백업 파일/참조 검사와 합성 첨부 자동 회귀를 실제 운영 첨부 열람과 구분한다.
이는 복원 및 새 코드의 조회 호환성 증거이며 운영 전환이 아니다.

운영 기준 health는 `status=ok`, 버전1.9.0, `0020_bottle_revision`, DB/schema/worker 준비 상태였다.
태그 후 실제 전환 직전 새 백업을 다시 만들었으며, 운영 전환과 별도의 배포 후 결과는 F절에 기록했다.

## E. 독립 검토와 반영

구현 담당과 다른 검토자가 데이터 보존·동시 수정·계정 전환·부분 실패와 현재 문서를 확인했다.
확정 결함에는 관찰 가능한 회귀를 추가한 뒤 수정했고 A절 최종 검사에 포함했다.

- 서버/로컬 원어 부분 검색 차이와 일본어 탁점 손실을 고쳤다.
- 복구 직후 시음이 더 최신인 동기화 기록을 가리던 우선순위를 버전 비교로 고쳤다.

  선택 병수 표시와 기존 SKU 평균 원가 정책을 맞췄다.
- 관심 구매 전환의 늦은 성공이 다른 계정 또는 재진입한 화면의 새 초안을 지우거나 이동시키던
  문제를 계정 세대·mounted·제출 초안 버전 검사로 고쳤다. 응답 유실의 동일 요청 재시도는 유지했다.
- 브라우저에서 발견한 숙성연수 시음 맥락500, 모바일 표/본문 대비, 탐색 용량·도수 단위를 보완했다.
