## R1 쓰기 내구성 (`feature/review-write-durability`)

### 재현과 변경

1. **응답 전 commit(B1).** `db_session`이 기본 범위 의존성이라 FastAPI 0.141.1이 응답을 보낸 뒤
   commit했다. 새 테스트에서 commit 실패를 주입하면 기대 500, 실제 201로 실패했다.
   `Depends(db_session, scope="function")`로 바꿔 응답 직렬화 뒤·전송 전에 commit한다.
2. **온라인 생성 중복(B9).** `POST /products`, `POST /purchases`에 선택 `request_id`를 추가했다.
   서버가 `uuid5(user_id, 종류:request_id)`로 id를 정해 이미 있으면 같은 행을 돌려주고, 이름·규격·
   병수가 다르면 409다. 웹은 `draftRequestId(form)`로 폼 초안 버전(revision 포함) 해시를 키로 쓴다.
   같은 초안 재전송은 같은 키, 수정·저장 후에는 새 키다. 구매처는 기존 `(user_id, name)` 유일성과
   목록 재조회로 이미 중복이 막혀 바꾸지 않았다.
3. **오프라인 연속 수정의 기준 시각(B7).** 보내지 않은 수정 뒤의 수정이 낙관적 기기 시각을
   `base_updated_at`으로 써서, 앞 수정이 충돌해도 뒤 수정이 다른 기기 변경을 덮어썼다.
   `enqueue`가 같은 행의 대기 중 수정에서 서버 기준 버전을 이어받는다. 수정 전 테스트는
   `[원래, 낙관값]`으로 실패했고 수정 후 두 명령 모두 원래 서버 버전을 기준으로 삼는다.
4. **실패한 병 동작 폐기 범위(B8).** 이미 있는 병의 `set_remaining` 실패를 폐기하면 같은 병의
   시음까지 의존 명령으로 지웠다. 수정·동작 실패의 의존 명령을 `expected_operation_id`·
   `origin_operation_id`로 이어진 명령으로 한정한다. 생성 실패는 기존처럼 참조 명령을 묶는다.

   데스크톱에서 숨었으므로 항상 보이는 목록으로 바꿨다. jsdom은 CSS를 적용하지 않으므로

   수정 전 코드에서 두 검사 모두 실패했다.
2. **도넛 범례 색(B14).** 조각은 0값을 뺀 뒤, 범례는 빼기 전 순번으로 색을 정해 개봉 0병일 때

   실패했다.
3. **자동완성 강조(B15).** CSS가 `li.active`를 대상으로 했지만 후보는 `div[role=option]`이었다.
   선택자를 `[role="option"]`으로 바꾸고 44px 높이를 준다.
4. **화면 전환 스크롤(B28).** 다른 화면이나 다른 제품 상세로 가면 맨 위에서 시작한다. 상세 →
   같은 목록 복귀와 상세 안의 시음·병 선택은 기존 위치 복원을 유지한다(`shouldResetScroll`).
5. **동기화 패널(U1).** 패널에 높이 제한·내부 스크롤과 고정 헤더를 주고, 600px 미만에서는 하단

6. **매장 모드 진입(U5).** 홈 바로가기 첫 항목으로 추가했다.

### 재현과 변경

1. **nginx 헤더 상속(B3)·CSP(F6).** 운영 `curl -sI https://…:8080/`(읽기 전용)에서 `X-Frame-Options`·

   수준 헤더를 끊기 때문이다. `docker/security-headers.conf`를 server와 각 location에 포함하고 CSP·

2. **Secure 쿠키(B4).** nginx가 `X-Forwarded-Proto $scheme`(항상 http)으로 덮어써 앞단 HTTPS가 API에
   전달되지 않았다. nginx는 들어온 값을 보존하고(없으면 `$scheme`), API는 운영 환경이면 항상 Secure를
   붙인다. 실제 운영 `Set-Cookie`는 로그인 자격이 필요해 배포 전에는 확인하지 않았다.
3. **로그인 제한(B5).** 검사 → await(사용자 조회·Argon2) → 실패 기록 순서라 동시 요청이 모두 검사를

   세션 기록 길이 제한으로 로그인이 500이었다). 키 상한(만료 정리 후 오래된 키 축출), Argon2 스레드 실행.

4. **외부 수치·명세(B16).** `round(inf)`(JSON 1e400·400자리 숫자)와 `"search": "x"` 명세가 어댑터 경계

- **U11 인사이트.** 공란·0원을 섞은 최저가 대신 유상 최저가를 보이고, 고아 기록 상세의 UUID를 기록
  종류·날짜·번호로 바꿨다. 근거 금액은 `formatMoney`로 쓴다.
- **U12 차트.** 선 차트의 `role="img"`가 대체 표를 가리던 문제를 막대·도넛과 같은 `figure`로 고쳤다.
  SVG 팔레트 3번이 위험색이었고 CSS 토큰과 달랐다 → CSS와 같은 살구색, 일치 테스트 추가.
- **U13 코드 분할.** 9개 드문 화면을 `React.lazy`로 나눠 첫 JS가 888KB → 762KB(gzip 269 → 236KB, 최종 빌드).
  서비스 워커 precache가 나눈 파일도 받는다. 배포 뒤 옛 파일을 못 찾으면 새로고침을 안내한다.
- **U14 제목.** 페이지 h1 중복을 `page-title` h2로 맞추고 상세 탭 제목에 제품명을 넣었다.
- **U2 관심 행 안 편집.** 수정·삭제 확인·구매 전환을 누른 행 아래에 펼치고 그 행으로 스크롤한다.
- **U6 상세 구조.** 탭으로 숨기면 정정·근거 이동이 가리키는 구매·시음이 사라져, 내용은 그대로 두고
  병·시음을 구매 이력보다 먼저 두며 "병·시음/구매/가격·외부" 바로가기(해시 라우터와 겹치지 않는 버튼)를
  더했다.
- **F1 매장 모드 관심.** 온라인에서 받은 관심·활성 감시 목표가를 계정 DB `sync_meta`에 저장하고,
  매장 모드에서 검색어와 맞는 관심·목표가를 보인다. 오프라인은 저장 시각과 함께 읽기 전용. 저장 시각은
  실제로 받은 시각(`dataUpdatedAt`)이고, 캐시로 다시 그리거나 다른 탭보다 먼저 받은 목록은 더 늦은 저장본을
  덮지 않는다.
- **F3 해외 구매.** 구매 추가에 통화·외화 단가·환율을 넣으면 원화 실구매가를 원 단위로 반올림해 채우고
  구매 이력에 외화 단가를 함께 보인다. 서버는 원화 통화의 외화 단가와 1% 넘는 환산 차이를 거부한다.
  처음엔 원 단위 일치를 요구했으나 기존 계약 테스트(46.67 USD × 1431.9 → 66,815.79원, 줄여 적은 환율)가
  실패해 1%로 넓혔다.
- **F4 별칭 앞부분 검색.** "발렌"·"글렌리"로 영문 제품을 찾는다(서버·웹 같은 표 `ALIAS_PREFIX_PARITY`).

  선형 역방향 스캔으로 바꾸고 제품 검색어를 300자로 제한했다(2만 자 질의 0.046초).

  "관측가 100ml당"을 더했다. 정가 기준 `price_per_100ml`과 이름을 구분한다.

### 자체 검토 반영

PR 전에 R6 변경만 읽기 전용 리뷰어에게 맡겨 7건을 받았고 모두 재현 테스트로 확인해 고쳤다.

1. **관측가 100ml당.** 모르는 수량(`units: null`)을 1병으로, 세트·추천가·검색 요약·품절·조건 미상 관측과
   0원을 일반 단품가로 계산했다. 서버 가격 비교 묶음(`offers.py`)과 같은 조건(원화·0원 초과, 용량·정수
   수량, 세트 아님, 판매 조건 7개를 모두 앎)일 때만 계산한다.
2. **매장 관심 신선도.** 온라인이지만 목록 조회가 실패·대기 중이면 오래된 저장본을 시각 없이 보였다. 이번에
   받은 목록이 있으면 그것을, 없으면 저장본을 "저장본(… 기준)"과 함께 보인다.
3. **목표가 용량.** 저장본 목표가에 감시 용량이 빠져 "700 / 1750ml · 목표 5만원"처럼 섞여 읽혔다. 목표가에
   감시 용량을 함께 적는다.
4. **인사이트 범위.** 저장한 주종이 삭제·병합되면 선택 상자는 "전체"인데 지표는 모두 0이었다 → 전체 주종으로
   계산한다. 모르는 상태 값은 전체로 되돌리고, 자정을 넘긴 탭에서 "오늘까지"로 둔 종료일(과 기본 90일 창)은
   오늘로 따라오게 저장한 날(`day`)을 함께 둔다. 직접 고른 날짜는 유지한다.
5. **확인창 Escape.** 배경을 눌러 포커스가 body로 빠진 뒤 Escape가 아래 동기화 패널을 닫았다. document 캡처
   단계에서 받아 확인창만 닫는다.
6. **확인창 포커스 복귀.** 접히는 메뉴 안 삭제 버튼에서 열면 닫힌 뒤 포커스가 사라졌다. `returnFocus`로 메뉴
   버튼을 지정하고, 요청마다 확인창을 새로 그려 앞선 요청의 복귀 위치를 이어받지 않는다.
7. **외화 정합성.** 원화 실구매가 없이 외화 단가만 보내면 실구매가 미상으로 저장됐다 → 환산값을 저장한다.
   구매 이력은 1% 넘게 어긋난 외화 기록(수정·레거시)에 "원화 실구매가와 다름"을 붙인다.
- 이연: 구매 수정(`PATCH /purchases`)과 오프라인 동기화 수정의 외화 정합성 검증. 웹 수정 폼에 외화 칸이 없어
  검증만 넣으면 외화 구매의 실구매가를 고칠 길이 막히므로, 수정 폼 외화 입력과 함께 후속으로 둔다.
- RED→GREEN: 위 7건의 테스트(`InterestsPage`·`StoreModeInterests` 3·`InsightsDashboard` 2·`ConfirmDialog` 2·
  `ProductDetail`, API 1) 모두 수정 전 실패 확인. 매장 저장본 시각 2건(`dataUpdatedAt`, 더 늦은 저장본 보존)도
