## 릴리스 변경·검증

패키지3곳과 두 lockfile의 앱 버전을1.7.0으로 일치시켰다. 의존성 버전과 DB schema는
기능 수용 기준과 동일한0018이다. 버전 일치 검사와 영향 검사, 필수 PR CI 및 릴리스 CI를
통과한 exact main SHA만 태그·이미지로 게시한다.

버전 일치·Ruff/format/ty·시크릿 검사 통과. 버전 응답 관련 health9개와 전체 웹634개/
branch81.09%·빌드가 통과했다. 변경은 버전·이연/수용 문서이며 기능 코드는 기준 main과 같다.

운영 변경 전 최신 DB/uploads 백업, 별도 암호화 비밀 복구와 실제 격리 복원·migration·
합계/참조/암호문 대조를 수행한다. 운영 실제 기록·원본·키는 이 공개 기록에 넣지 않는다.
기존1.6.1 이미지는 유지했고 DB 컨테이너/volume을 교체하지 않았다. 실제 결과는 아래에 기록한다.

## 실제 릴리스·배포 결과

- 버전 PR [#144](https://github.com/jihoon22-lee/SoolJang/pull/144)의 필수 CI가 통과한 뒤
  main `f1c5bbc7cf20492d7ba08968c071ebf90b264046`에 `v1.7.0`을 태그했다.
  [릴리스 CI](https://github.com/jihoon22-lee/SoolJang/actions/runs/34105371427)는 전체
  Python·웹 검사, API/웹 이미지 빌드·GHCR 게시, GitHub 릴리스 생성을 모두 완료했다.
- [릴리스](https://github.com/jihoon22-lee/SoolJang/releases/tag/v1.7.0)의 API/웹 이미지
  version/revision label과 content ID·registry digest를 대조했다. 실제 운영 schema는
  `0018_price_watch`이며 API/web/db가 모두 healthy다. [비밀·개인 기록을 제외한 실행 metadata](assets/v170-deployment-results.json).
- 운영 API를 잠시 중지해1.6.1 최신 DB/uploads 백업을 만들고 원 서비스를 재개한 상태에서
  별도54329 DB에 실제 복원·0018 migration·drift·인증 API9종을 먼저 확인했다. 실제 첨부가
  없는 운영 데이터는 빈 uploads/참조의 보존을 확인했고 이미지 디코딩·인증 GET은 B09 합성 PNG
  증거와 구분한다. 실제 사용자 비밀번호를 재설정하지 않고 짧은 검증 세션으로 API를 확인했다.
- 최종 전환에서도 web/API 쓰기를 중지하고 새 직전 백업·별도 빈 DB 복원을 수행했다.
  최초 해시 대조는 Docker DB의 UTC와 검증 DB의 Asia/Seoul 직렬화 차이로 중지됐다.
  운영 migration 전에 기존 서비스를 재개했고, UTC·C collation으로 대조 기준을 통일하니
  모든 원래 테이블/컬럼 값이 같았다. 데이터를 고친 것이 아니다. 새 직전 백업으로 재실행해
  복원 대조→명시 migration→원래 컬럼 대조→API readiness 순서를 통과했다.
- 기존 `.env`는 마스터 키/DB 인증 등 값을 유지하고 버전만1.7.0으로 바꿨다. Windows의
  계정별 DPAPI 암호화와 사용자/SYSTEM ACL로 별도 런타임 복구본을 만들고 복호화 바이트
  대조를 확인했다. 키나 평문 `.env`는 일반 백업·공개 artifact에 넣지 않았다. 이 경로는
  동일 Windows 계정의 DPAPI 프로필 보존이 필요하며 Windows 계정 복구까지 대체하지 않는다.
- 기존 소스·OCR 암호문/설정의 복호화를 확인했다. 앞서 사용 승인받은 Exa 키를 새 수동 검색
  연결에 암호화 등록하고 분6회·UTC 하루20회 한도를 설정했다. 연결 확인1회와 실제 검색1회가
  성공했고10문서를 받았다. 새 탐색은 생성형 요약/LLM을 호출하지 않았다. 기존 같은 제공자
  연결이 있었다면 덮어쓰지 않는 경로로 처리했다. 새 가격 감시/푸시는 자동 생성·동의하지 않았다.
- 새 연결을 포함한1.7.0 DB/uploads 백업도 생성·검증한 후 웹을 열었다. 운영 HTTPS에서
  실제 Chromium으로 제품/동기화·탐색·관심·가격 감시·위치/실사·품질·연결 화면과 SW를
  확인했다.390px 가로 넘침·pageerror·API HTTP 오류는0이다. 실제 기록 화면은 캡처하지 않았다.
- 마지막 임시 검증 세션을 제거했다. 앱 조회 후 정상적으로 변하는 인증 활동 시각을 제외하면
  기존 인증 ID/토큰/만료·개인 기록·키·고정의 원래 값이 보존됐다. 운영 합계는 직전 백업과
  대조했으며 개인별 수치는 공개 기록에 넣지 않는다.

운영 주소는 기존 [술장 HTTPS](https://main.tail30f401.ts.net:8080)다. 최신 화면이 바로 보이지
않는 기존 PWA는 입력을 저장한 뒤 새 버전을 적용한다. 승인 이연 #142/#143만 후속으로
유지하며 나머지 v1.7.0 마일스톤을 완료한다. Windows 전체 재부팅은 이번에 실행하지 않았고,
no-recreate 컨테이너 보존은 B09의 별도 실제 검증으로 확인했다.
