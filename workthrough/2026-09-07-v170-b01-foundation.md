# v1.7.0 B01 — 외부 요청 경계·상태·평가 기준

관련: WP01 [#119](https://github.com/jihoon22-lee/SoolJang/issues/119), WP04
[#122](https://github.com/jihoon22-lee/SoolJang/issues/122). R01~03/R07~14/R24의 기반,
S02/S04~07 검증 계약. 전체 마일스톤 수용과 구분한다.

## 변경과 판단

외부 요청이 redirect를 따라간 뒤 host를 검사하고 조회 버튼 단위 메모리 카운터만 쓰던
경로를, **요청 전 URL/DNS/IP 검증 + 실제 연결 IP 고정 + 각 HTTP 시도 영속 예약**으로 바꿨다.
원래 TLS Host/SNI를 유지하고 robots·상세·redirect로 비밀을 보내지 않는다. 압축 전후 크기·
전체 deadline·query/redirect/retry·worker 동시성 상한을 둔다. 오류/원문 반사로 비밀을 저장하지 않는다.

`0013_external_request_usage`는 기존 데이터/암호문을 보존하며 요청 카운터·설정 revision·
probe 결과 코드를 추가한다. 빈 키 입력은 기존 암호문을 유지하고 복호화 실패는 출처별 오류다.
설정 변경 후 과거 정상/캐시는 현재 검증으로 재사용하지 않는다. 프리셋 일괄 갱신의
`any(generator)` short-circuit를 제거해 모든 대상과 override를 함께 처리한다.

UI에는 최근 결과/검증 시각, 설정 변경 후 재검증, UTC 하루 요청 예약/한도를 보여준다.
예약은 과금/잔액과 다르며 송신 직전 중단 시 보수적으로 유지한다. 직접 사용하는 httpcore를
런타임 의존성에 명시했고 기존 버전 1.0.9를 사용한다.

소스별 [정책/실현 가능성](../docs/plans/v1.7.0/sources.md),
[최소 계약](../docs/specs/v1.7.0-discovery.md),
[합성 평가 기준선](../docs/plans/v1.7.0/baseline.md)을 기록했다. NAVER API HUB 이관과
쇼핑 검색 종료, 각 소스의 권리/실연결 조건을 현재 지원 여부와 구분한다.

## 남은 수용

기존 매칭의 배치/캐스크 오탐과 다국어 후보 누락은 B04에서 같은 fixture로 개선한다.
허용 실소스의 가격/후기 보관·재표시, 신규 검색 제공자 인증, 실제 다중 판매 조건/지점
완전성은 이 PR의 mock/공개 구조 조사로 완료하지 않는다. 기존 계정/등록 상태는 사용자
입력을 요청했으며 키 값은 채팅/저장소에 요구하지 않았다. source schema·공통 요청 계약은
B03/B04/B05가 소비하고 B02/B06은 별도 격리 공간에서 진행한다.
