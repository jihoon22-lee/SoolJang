# v1.8.0 ① — 정확성 수정 (코드 리뷰 반영)

2026-10-04 전체 코드 리뷰에서 확인한 정확성 결함을 고친다. 메인 [#147](https://github.com/jihoon22-lee/SoolJang/issues/147),
브랜치 `feature/v180-correctness`. 결정은 `docs/plan.md` D212~D216.

## 변경

**날짜·시간대 (D212)**
- 웹: `todayLocal()`로 개봉·소진·증여·시음·구매 기본 날짜를 기기 시간대로 계산한다.
- 서버: `SOOLJANG_TIMEZONE`(기본 Asia/Seoul)과 `clock.local_today()`. slim 이미지용 `tzdata` 의존성.

**동기화 (D213)**
- 병 상태 전이 충돌은 `conflict` + 서버 스냅샷 + ConflictLog로 응답하고 배치를 계속한다.
- 오프라인 시음은 `reconcile` 모드로 기록을 보존한다(잔량 부족이면 0·소진, 내보낸 병은 상태 유지).
- 클라이언트는 전송 실패가 있어도 pull 한다(보호 id 유지, 원래 오류를 우선 표시).
- pull 첫 페이지 `rewind`(30초)로 늦게 커밋된 트랜잭션의 행을 놓치지 않는다.
- 동기화 경로도 온라인과 같은 검증을 거친다: 주종 삭제 시 하위/소속 검사, 바코드 정규화,
  통화 코드 검증, 생산자·시음 규격 소유권.
- 온라인으로 만든 제품의 로컬 미러는 기기 시계와 무관하게 다음 pull로 덮어쓴다(`reconcile_ids`).

**삭제·조회 정합성 (D214)**
- 제품 삭제가 규격·구매·병까지 연쇄 soft delete(온라인·동기화·오프라인 낙관적 반영 모두).
  삭제 전 확인창에 함께 지워질 구매·병 수를 보여준다.
- 이전에 남은 하위 행은 보관/실사 병 목록·`/bottles`·구매처 집계·최근 시음에서 제외한다.

**지표 (D215)**
- 할인율은 정가 기록(0원 초과) 구매만 사용(Python·SQL·TS·공통 fixture 동일).
- 가격 순위에서 0원 제품 제외(서버·오프라인 동일). 통계 계산 기준에 0원 구매 수와
  할인율 기준 구매 수를 실제로 센다(하드코딩 제거).

**병·시음 (D216)**
- 소진 되돌리기 시 잔량 0 → 미기록. `POST /bottles/{id}:remaining`·동기화 `set_remaining`.
- 개봉일보다 앞선 시음은 개봉일을 당긴다(소진일<개봉일 제약 위반 방지).

**기타**
- 바코드 감지 즉시 카메라 track 정지(네이티브 경로가 스트림을 남기던 결함).
- 레거시 임포트: 실패 행의 registry·건수 롤백, 사용자별 advisory lock, DB 예외 원문 비노출.
- 정리(cleanup): `owned_many` 한 번의 `ANY + FOR UPDATE`, 누락 id를 메시지로 보고.
- 보관 위치 점유 수는 재고(미개봉·개봉)만. 구매 목록 N+1 제거, `/bottles` `offset`.
- 주종: 생성/이동 시 상위 소유권, 트리 CTE 재귀 항 `user_id`, 병합 깊이 상한 검사.
- 온라인 제품 생성의 잘못된 바코드는 422(이전 500).
- 오프라인 로그아웃은 다음 온라인 실행에서 서버 로그아웃을 마저 수행하고 안내한다.
- skip-link가 해시 라우터에서 홈으로 이동하던 문제, 제품 상세의 조용한 실패 표시.
- 테스트 기본 DB 폴백을 운영 포트(5432) 대신 격리 54329로 변경(CI는 명시 URL 사용).
