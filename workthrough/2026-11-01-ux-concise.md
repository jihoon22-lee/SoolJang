## PR-A 목록·시각·문구 (`feature/ux-concise-list`)

### 변경

- 구매 참조(D264): `purchaseReference`가 용량·구매일·구매처(같은 제품 안)가 겹치는 구매가 있을
  때만 짧은 참조를 돌려준다. 병 목록·빠른 시음·시음 이력·정정 폼·재고 실사·구매 이력 표의
  여섯 호출부를 맥락 기반으로 바꿨다. 규격 정정 버튼의 접근성 이름은 구매일·구매처로 읽힌다.
- 내 술 목록(D263): 모바일 행을 이름·재고 / 주종·용량·판본 / 평단가·100ml당·내 평점 한 줄로
  줄였다. 카드 전체가 누르는 영역(44px 이상)이고, 규격이 하나면 규격 요약을 반복하지 않는다.
  여러 규격·조건 범위에서는 규격별 재고·실평단가 칩과 규격 이동(R01·R02)을 유지한다.
- 검색: 검색창을 접지 않고 나머지 필터만 접는다. 접힌 단추는 "필터 N"으로 적용 중인 조건 수를
  보인다. "/" 단축키는 펼치지 않고 바로 검색창으로 간다. 순서 편집 목록에서 검색은 빠진다.
- 데스크톱 표: 내부 스크롤(최대 702px)을 없애고 페이지가 스크롤하며 머리글은 앱 헤더(72px)
  아래에 붙는다. 개봉/미개봉 내역을 배지 옆에 두어 행을 한 줄로 줄였다.
- 시각(D262): 하단 탭에 아이콘을 더하고 현재 화면은 브라스 블록 대신 글자색과 막대로 표시한다.
  제품·주종·구매처·재고 실사·통계의 내부 이동 이름은 본문색·무밑줄(D240)이다. 모바일 동기화
  표시도 점만 두지 않고 "최신 상태" 같은 문구를 보인다. 쓰이지 않던 홈 주종 막대 CSS를 지웠다.
- 메뉴·문구: 설정 메뉴에 매장 모드를 두고 메뉴 안 "설정"을 "앱 설정"으로 바꿨다. 탐색·관심
  안내에서 요청 상한·내부 정책 문장을 사용자 말로 바꿨다.

### 독립 검토와 반영

구현 담당 외 검토(코드 읽기 전용)가 차단·데이터 손실 경로 없이 아래 7건을 보고했다. 모두 실제
브라우저나 실패하는 테스트로 재현한 뒤 고쳤다.

| 지적 | 재현 | 반영 |
|---|---|---|
| 900~1400px·조건 열에서 표가 결과 영역보다 넓어 페이지 전체가 가로로 밀림 | 1024px 문서 폭 1,095px, "재고 있음"에서 표 1,111px(1280·1366px도 넘침). 재고 칸이 한 줄 306px | 표가 넘칠 때만 표 안에서 가로로 넘기고 맞으면 머리글 고정 유지. 재고 칸은 배지·개봉 내역 한 줄 + "조건 내 재고" 아랫줄, 주종 최소 폭 6.5rem |
| 머리글 위치 72px 고정 | 헤더는 줄바꿈으로 높이가 바뀜 | 실제 헤더 높이(ResizeObserver)를 `--app-header-h`로 사용 |
| 선택 모드 확인란 약 20px, 빗맞으면 상세 열림 | 카드 전체가 상세 링크 | 왼쪽 44px 여백 전체가 확인란 영역(390px 실측 44×카드 높이, 모서리 눌러도 선택) |
| 순서 편집 경계가 7번째라 접히는 "국가"가 상시 쪽에 보임, "기본 순서로"가 검색창을 두 번 저장 | 새 테스트 2건 수정 전 실패 | 검색창 아래 실제 상시 수(6)로 경계·안내, 저장 전 검색창 한 번만 |
| 보관·실사 행마다 전체 병 비교(O(n²)) | 코드 경로 | 맥락별로 한 번 묶는 `purchaseReferences`, 보관·실사·빠른 시음이 재사용(행별 계산과 같은 결과를 테스트로 고정) |
| 같은 날·같은 구매처의 다른 용량 구매의 정정 단추 이름 중복 | 새 테스트 수정 전 실패 | 이름에 용량 추가 |
| D263 문구(대표 가격 하나)와 구현(평단가·100ml당·평점 한 줄) 불일치 | 문서 대조 | D263을 구현에 맞춰 갱신 |

검증 중 필터 선택만 바꿔도 이탈 확인창이 뜨고 새 버전 적용이 미뤄지는 기존 동작을 함께 확인했다.

### CI와 의존성 감사

PR #191 첫 CI에서 Python 품질이 두 가지 이유로 실패했다. 둘 다 PR-A 변경과 무관하다.

- pip-audit: email-validator를 거쳐 들어오는 `dnspython 2.8.0`의 CVE-2026-114605(수정 2.9.0)가 새로
  공개되어 main을 포함한 모든 PR이 막혔다(#190도 같은 이유로 실패). D259와 같이 lockfile의 해당
  간접 의존성만 2.9.1로 올린 별도 커밋을 이 묶음에 넣었다. 로컬에서 CI와 같은 `uv export` +
  `pip-audit --strict`가 "No known vulnerabilities found", 인증·초기 설정·이메일 API 테스트 58건 통과.
- pytest: 1,853 통과 중 1건이 CI Postgres 연결 한도 초과("too many clients")로 준비 단계 오류.
  같은 커밋의 재실행으로 확인한다.

## PR-B 홈·통계 (`feature/ux-concise-home-stats`)

### 변경

- 홈(D265): 마신 술·산 술 기록 두 행동, 현재/미개봉/개봉 중·재고 원가 한 줄, 열린 병 5개(전체 보기
  유지), 최근 시음 3건만 둔다. 관리 바로가기는 설정 메뉴(매장 모드·보관·실사·데이터 품질·가격 감시가
  이미 있음), 랭킹은 통계 랭킹 탭, 주종별 보유는 통계 주종별 탭, 최근 등록은 내 술 정렬로 옮겼다.
  첫 등록 전에는 "산 술 기록" 안내 한 줄을 보인다. 넓은 화면은 열린 병과 최근 시음을 두 칸으로 둔다.
- 열린 병: 잔량 게이지(정보 요소, 미기록은 빈 병이 아닌 빗금, D242)와 "한 잔" 단추. 한 잔은 그 병으로
  빠른 시음을 연다. 다른 병의 선택 초안이 남아 있어도 고른 병으로 열고, 다른 병의 입력은 병별
  초안에 그대로 남는다(D248). 기록으로 병이 소진되어 단추가 사라지면 초점은 "마신 술 기록"으로 간다.
  이름·잔량 글자 영역 전체가 병 상세로 가는 44px 이상 누름 영역이다.
- 최근 시음: 행 전체가 그 기록을 연다. 고치기·삭제는 기록 화면에서 한다(D261). 0점과 평점 없음을
  구분해 보인다(QS05).
- "산 술 기록": 등록 폼을 연 내 술로 간다. 표시를 해시에 남기지 않아 새로고침·뒤로가기로 폼이 다시
  열리지 않고, 작성 중이던 등록이 있으면 툴바 단추처럼 그 등록을 이어 연다.
- 통계(D266): 주종별 탭 맨 위에 주종별 보유(상태별 숫자 → 병 목록, QS07), 상세 합계·주종별·랭킹의
  계산 기준은 화면 끝 하나로 모았다. 인사이트 첫 화면은 기간 칩(최근 90일·올해·전체 기간·직접
  설정)과 적용 범위 요약이고 날짜·주종·상태 입력은 접힌다. 직접 고른 범위·잘못된 범위로 돌아오면
  펼친다. 카드마다 반복되던 일반 계산 설명은 끝의 "계산 기준"으로 모으고 잔량 미확인·직전 기간·표본
  1건처럼 수치에 딸린 문장과 근거 이동은 그 자리에 둔다(D246).
- 차트의 화면 낭독기용 표(sr-only)가 1px 너비를 무시하고 펼쳐져 390px 통계를 2px 가로로 밀던 기존
