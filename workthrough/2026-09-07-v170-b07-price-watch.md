# v1.7.0 B07 — 가격 관측·목표가·별도 동의 알림

WP10 #128, R08/R14~R16/R21/R24, S05/S11. 허용된 실제 가격 관측에서 판매 조건을
선택해 목표가를 저장하고, 수동 조회·정기 조회·웹 푸시 동의를 구분한다. 같은 작업이나
전송의 재처리, 설정 변경 중 늦게 도착한 응답이 중복 알림을 만들지 않도록 DB 원장을 둔다.

## 변경과 결정

- `domain/price_watch.py`는 네트워크 없이 제품 고정·판본 확인·규격·통화·판매 조건·재고·
  신선도를 판정한다. 감시 기준은 실제 저장된 관측에서 만들고, 캐시·부분 성공·last-good을
  새 관측으로 쓰지 않는다. 기존 B05 `lookup_interest` 경계를 선택한 소스 하나로 호출한다.
- `application/price_watch.py`, `price_watch_worker.py`는 감시 설정, 일정 발생, 작업 임대,
  원자적 알림/전송 생성과 복구 상태를 관리한다. 감시→작업 잠금 순서, 매 요청 전 상태 확인,
  결과 저장 시 `populate_existing` 재조회로 동시 변경과 ORM identity map의 오래된 상태를
  막는다. 설정 중지와 결과/실패 저장의 두 세션 교착 재현 테스트를 포함한다.
- `0018_price_watch`는 `0017_data_inventory` 다음에 감시·작업·앱 알림·암호화 구독·푸시
  전송 5개 테이블을 추가한다. 기존 관측과 관심 대상은 유지하고 자동 감시를 생성하지 않는다.
  정기 조회와 푸시 opt-in은 각각 기본 false다. 사용자 API는 인증·소유권·CSRF 경계를 따른다.
- `infrastructure/web_push.py`는 `http-ece` aes128gcm과 기존 cryptography로 표준 Web Push를
  작성한다. 허용된 공개 HTTPS host, redirect 금지, 10초 timeout, TTL 300초를 적용한다.
  endpoint/수신 키는 기존 마스터 키로 암호화하고 목록에는 fingerprint만 제공한다.
  해제·만료는 암호문을 NULL로 제거하며 복호화 실패는 원본을 보존한다.
- 응답 불명/프로세스 중단의 `sending`은 `unknown`으로 남겨 자동 재전송하지 않는다.
  429/503 명시 거절만 최대 3회 재시도한다. 404/410 만료와 VAPID 교체를 구분한다.
  서버 접수 성공은 실제 화면 표시 성공으로 표시하지 않는다. 용량 상한과 시간 제한은
  [가격 감시 계약](../docs/price-watch.md)에 정리했다.
- 웹에 제품/관심 가격 이력, 목표가 폼, 임시 입력 복구, 감시·알림 페이지와 개별 기기 구독을
  추가했다. 제품의 관심 저장 연결은 B05 통합 UI에서 이어진다. `price-push.js`는 일반 문구와
  이벤트 ID만 사용하며 동일 origin의 고정 화면으로 이동한다. Worker의 중복 기록과
  브라우저 VAPID 교체/로그아웃 구독 종료를 검증했다.

실브라우저는 별도 합성 전용 DB `sooljang_pricewatch_browser_test`, API 8222/웹 5182를
사용했다. UI에서 가격 이력→목표가 저장→정기/푸시 기본 꺼짐 확인→목표가 입력 후 reload와
복구→푸시만 동의→기기 등록→수동 조회→새 관측과 앱 알림 1개→푸시 서비스 접수→정기
15분 동의→일시 중지를 실행했다. 첫 수동 조회 전 `last_checked_at=null`로 화면 진입이
조회하지 않음을 확인했다. 실제 브라우저 알림 권한·PushManager와 외부 provider/push HTTP는
합성 fixture/MockTransport로 대체했고 **실제 서비스 송신·잠금 화면 표시는 검증하지 않았다**.

민감정보 없는 합성 화면은 [모바일](assets/v170-b07-mobile.png),
[데스크톱](assets/v170-b07-desktop.png), 키·본문을 제외한

실제 사용자 데이터나 provider 자격증명은 사용하지 않았다.

## 미실행과 통합 범위

- 30 skip은 실제 레거시 파일, 성능 opt-in, 별도 복구 opt-in 등 명시된 외부 입력 조건이다.
  기존 Starlette httpx deprecation 및 웹 bundle 크기 warning은 남아 있다.
- 실제 push 구독/수신, 운영 VAPID 발급·교체, 유료 provider 호출, 운영 배포는 미실행이다.
- 전체 백업 bundle의 B07 원장·구독 암호문 포함 dump/restore와 복구 후 불확실한 전송 보존은
  B09 통합 복구 실행에서 확인한다. 여기서는 DB 단위 migration과 재시작 상태 전이를 검증했다.
- 본 묶음은 구현·로컬 검증이다. 최신 B05 UI 통합 후 전체 CI·복구·릴리스 수용은 주 담당자가
  합친 결과로 기록한다. `docs/plan.md`도 주 담당자가 통합 갱신한다.
