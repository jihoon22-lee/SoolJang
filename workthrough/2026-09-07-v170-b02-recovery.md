# v1.7.0 B02 — 전체 백업·격리 복구·스키마 readiness

최초 기준 SHA `b46bc6f`, B01 `e9c52b5` 통합 후 `feature/v170-recovery` 변경. 관련 WP03 #121,
R20~21/R24·S03/S10/S11의 복구 기반을 구현한다. 운영 릴리스/전환과 Windows cold start
실기는 이 변경의 테스트 결과로 완료 처리하지 않는다.

기존 `backup.sh`는 DB만 저장하고 `pg_restore` 실패 후에도 완료 메시지를 냈다.
이제 `scripts/recovery.py`가 DB+uploads+manifest/checksum을 임시 디렉터리에서 검증한 뒤
완료 이름으로 게시한다. `--verify`는 파일/키/목차 검사이며 `--restore`는 원본과 다른
빈 격리 DB·새 uploads 경로에 실제 복원한다. 기존 DB/볼륨에 `--clean`으로 덮어쓰지 않는다.

- 생성에는 모든 쓰기 중지 확인이 필요하다. Compose에서는 실행 중 API와 남은 DB client
  세션도 검사한다. DB snapshot과 파일 복사의 일관성 경계·획득 시각을 기록하고 첨부 참조,
  크기·SHA-256·행 수·schema를 대조한다. 파일/디렉터리는 0600/0700이며 fsync 후 게시한다.
- 중단·손상·누락·키 불일치·여유공간 부족을 실패로 반환한다. 복원은
  `--exit-on-error --single-transaction`을 사용한다. 파일 게시 이후 운영 전환은 자동화하지 않는다.
- 보존은 검증된 완료 묶음만 대상으로 최소 1개를 남긴다. 기존 `.dump`·부분/손상 묶음·다른
  이름·symlink는 자동 삭제하지 않는다. 동시 백업은 파일 잠금으로 거절한다.
- 일반 백업에 `.env`/마스터 키 평문은 넣지 않는다. 별도 암호화 비밀 복구 매체에서 환경으로
  주입한 키를 암호화 확인 문장 및 DB `*ciphertext` 컬럼과 대조한다. 복호화 실패로 초기화하지 않는다.
- manifest의 `app_version`은 실제 배포 버전의 명시 입력(로컬은 설치 패키지)이고
  `backup_tool_version`과 분리한다. CLI의 DB 인자는 접속 URL이 아닌 이름만 받는다.
- `/health/live`는 DB와 무관한 생존, `/health/ready`와 기존 `/health`는 DB 연결 및
  **패키지 Alembic head 집합과 실제 revision 집합의 일치**를 검사한다. head를 하드코딩하지 않는다.
  구/미래/누락/추가 head는 503이다. 로그인·health 공개 경계를 유지한다.
- `docs/operations.md`에 이미지 준비→쓰기 중지/백업→migration→API readiness→웹/실제 기능
  검증→쓰기 재개의 순서와 실패/신규 데이터 보존 경계를 반영했다. WSL 자동 복구는
  기존 `--no-recreate`만 유지하며 migration·pull·자동 downgrade를 추가하지 않는다.

모의 DB 테스트를 실제 PostgreSQL 복원 증거로 세지 않았다.

## 제한과 후속 통합

- 운영 DB·실제 backups/uploads·실제 마스터 키·운영 컨테이너는 읽거나 변경하지 않았다.
  Compose의 `cp`/디스크 조회 경로와 Windows 로그온/cold start는 운영 실기 미실행이다.
- 대표 첨부는 복원된 유효 PNG 파일의 bytes/서명·checksum으로 열람했다. 현 앱의 attachments
  라우터가 POST만 제공하므로 인증된 이미지 GET/브라우저 열람은 추가 구현·실기 수용이 필요하다.
- Docker 이미지 실제 교체·볼륨/컨테이너 ID 보존·비밀 보관소 복구·신규 데이터 이후 rollback은
  운영 전환 시 별도 증거가 필요하다. 문서의 배포 절차를 실제 실행했다고 기록하지 않는다.
- 후속 WP의 신규 migration/암호화 키 이전은 각 WP의 합성 fixture·복구 검증을 추가해야 한다.
  이번 schema는 기준 SHA에 포함된 head이며 readiness는 통합된 패키지 head를 자동 판별한다.
- 전체 검사의 기존 Starlette/httpx deprecation과 Vite 큰 chunk 경고는 이번 범위에서 변경하지 않았다.
- `docs/plan.md`는 주 담당자가 B01 기반으로 통합했다. 운영 배포 수용 전에는 WP03 전체를 닫지 않는다.
