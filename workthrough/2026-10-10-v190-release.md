## 태그 전과 전환 직전의 두 차례 백업·복원

운영 API 쓰기를 중지하고 DB·uploads를 같은 완료 묶음으로 백업했다. DB 컨테이너는 유지했다.
각 묶음의 체크섬·첨부 참조·키 확인·덤프 목차를 검증한 다음, 별도 빈 DB와 새 uploads 경로에
실제로 복원했다. 첫 검증 후에는 운영0019의 기존1.8.2 서비스를 재개했고, 릴리스 대기 후
전환 직전에 다시 중지하여 최신 상태의 백업·복원을 수행했다.

| 구분 | 완료 백업 | 격리 대상 |
|---|---|---|
| 태그 전 | `sooljang-20261009T195414327575Z-b35a2ae2` | `54329/sooljang_v190_restore_20261010_pre_tag` |
| 전환 직전 | `sooljang-20261009T201333878988Z-d30bbd20` | `54329/sooljang_v190_restore_20261010_pre_deploy` |

정규 완료 묶음은 `/home/jihoon/sooljang-backups/`에 보관했다. 덤프·업로드·실제 기록·키는
저장소에 넣지 않았다. 기존 DPAPI 암호화 복구본과 현재 마스터 키의 일치도 메모리에서만
확인했다. 키를 출력·교체하거나 복호화 실패를 초기화로 처리하지 않았다.

두 복원본에서 다음을 모두 확인했다.

1. 복원 도구의 전체 행 수·schema·첨부 참조·파일 바이트·암호문 대조 통과.
2. 원본과 복원본의 전체 public 업무 행 해시 일치. 시간대 UTC·bytea hex·C 정렬로
   비교 표현 차이를 제거했다. 원문은 출력하지 않았다.
3. 복원본0019→0020 migration 및 `alembic check` 통과. 모든 기존 행·ID·암호문은 동일하고
   병 revision은 전체 행에 서로 다른 non-null 값으로 채워졌다. 비교에서 의도적으로 제외한
   것은 `alembic_version`과 새 `bottle.revision`뿐이다.
4. 실제 쿠키 로그인 후 제품·구매·병·시음/페이지·통계·보관·연결 및 정정 context/이력 조회 통과.
   임시 비밀번호와 세션 변경은 복원본 트랜잭션 안에서만 수행하고 전부 롤백했다.
   API 검증 후 전체 행 해시가 검증 전과 같은 것도 재확인했다.
5. 읽기 전용 트랜잭션의 독립 SKU 원가 산술, 사용자별 합계, 시음 커서 순서·중복 없음·맥락을
   확인했다. 운영 전환 후 같은 프로브도 통과했다.

대표 첨부 실파일 열람은 검증 대상이 없어 **미실행**이다. 전체 uploads 백업/복원 대조와
WP05/06의 합성 PNG 첨부·정정 보존 검증은 별도 근거다.

검증 완료 후 이번에 만든 격리 복원 DB 두 개와 임시 uploads 사본만 정리했다. 정규 완료
백업과 운영 DB·uploads는 유지했다. 운영 DB에서 pytest나 복구 테스트 초기화를 실행하지 않았다.

## 운영 전환과 보존

`.env`는 `SOOLJANG_VERSION` 한 항목만1.8.2→1.9.0으로 바꾸고 나머지 바이트를 보존했다.
`api`·`web` 이미지만 pull했으며 DB 이미지를 pull하거나 볼륨을 재생성하지 않았다.

최신 백업의 복원 검증을 마친 후 아래 순서로 실행했다.

```text
운영 API 중지
→ 운영 원본 해시 기록
→ 새1.9.0 이미지의 alembic upgrade head
→ 운영 원본/암호문 해시 및 0020 revision 채움 확인
→ api up --no-deps --wait (healthy)
→ web up --no-deps
→ 실제 운영 조회·PWA 확인
```

운영 마이그레이션 전후 전체 원본 해시가 일치했다. 기존 DB 컨테이너 ID·이미지·pgdata mount,
API uploads mount도 그대로였다. 이전1.8.2 이미지는 삭제하거나 prune하지 않았다.
0020 적용 후 구1.8.2 API만 다시 시작하는 동작은 하지 않았다. 향후 복구도 최신 데이터와
DB+uploads를 함께 다루며 자동 downgrade하지 않는다.

최초 PWA 확인 스크립트는 서비스워커 활성화와 자동 reload를 충분히 기다리지 않아
자산 비교가 한 번 실패했다. 설치/대기/활성화 상태와 실제 새 entry script를 기다리도록
검증을 보완한 뒤 통과했다. 앱 코드를 추가 변경하거나 검사를 건너뛰지 않았다.

운영 API 조회 프로브는 실제 컨테이너의 사용자별 서비스·스키마를 읽은 것이며, 운영 사용자의
비밀번호를 변경하거나 실제 사용자 세션으로 로그인한 검증은 아니다. 실제 로그인은 격리
복원본에서 확인했다. 로그인한 사용자의 offline 기록·응답 유실·업데이트 초안 보존은
[WP06 합성 PWA 수용](2026-10-10-usage-acceptance.md)의 별도 근거다.

실제 모바일 기기·카메라·웹 푸시·국내 가격 출처 수용과 Windows 재부팅은 이번 배포에서
새로 실행하지 않았다. #142·#143 이연을 유지하며 운영 자동 복구 설정은 변경하지 않았다.
