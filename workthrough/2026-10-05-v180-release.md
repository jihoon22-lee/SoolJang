①~⑤ 머지 뒤 실제 브라우저로 기록·수정·오프라인·통계·보관 흐름을 다시 써 보고, 어색하거나

브랜치 `feature/v180-release`. 결정은 `docs/plan.md` D224·D225.

## 써 보며 찾은 것과 고친 것

| 발견 | 고친 내용 |
|---|---|
| 모바일 제품 상세의 구매 이력이 가로 스크롤 표라 수정·분할·삭제 버튼이 화면 밖에 숨어 있었다 | 600px 미만에서 구매 한 건을 카드로 쌓는다(`purchase-cards`, CSS만). 용량별 표는 그대로 |
| 구매 수정 이력이 "구매처 없음 → 다른 구매처", "2500 → 2200"으로 읽혔다. 위치 이동 이력은 내용이 비었다 | 서버가 이력 행에 구매처·보관 위치의 지금 이름(`labels`)을 붙이고, 화면은 가격을 원 단위로, 이동은 "셀러 → 선반"으로 보인다(D225) |
| 내 술 카드의 평단가·100ml당·평점이 폭에 따라 마지막 쌍만 다음 줄로 떨어졌다 | 이름 위·값 아래 3칸 격자로 고정 |
| 500ml 맥주를 빠른 시음으로 고르면 30~150ml 프리셋뿐이라 "한 캔 다 마심"을 직접 입력해야 했다 | 남은 양을 알면 "남은 양 전부(Nml)" 프리셋과 "소진으로 기록" 안내. 알림도 "(다 마셔 소진 처리)"로 구분 |
| 레거시 데이터가 있으면 홈·통계의 주종별 보유에 "미분류"가 두 줄(가져오기가 만든 실제 주종, 주종 없음) 나왔다 | 주종이 없는 묶음을 "주종 미지정"으로 바꿨다(서버 통계·오프라인 통계·경로 표시·일괄 이동 문구, D224) |
| 동기화 창이 대기만 있어도 제목이 "동기화 문제"였고 항목이 `시음 기록 · record_tasting`처럼 내부 이름이었다 | 실패·충돌이 있을 때만 "동기화 문제", 아니면 "동기화 상태". 명령은 "병 소진", "시음 기록 · 2026-10-05"처럼 보인다 |
| 키보드로 메뉴를 고른 뒤 화면을 바꾸면 본문 전체에 금색 테두리가 생겼다 | 프로그램으로 초점을 받는 `main`의 outline만 지움(컨트롤 초점 표시는 유지) |
| 재고 실사를 시작하려면 이름을 반드시 지어야 했다 | 비워 두면 "YYYY-MM-DD 실사"로 시작 |

그대로 둔 것: 모바일 내 술 화면에서 검색 막대가 제목 위에 오는 순서(사이드바 레이아웃이 쌓인
결과지만 검색이 맨 위인 것이 자연스럽다), 100ml당 가격의 정가 기준 표시(기존 정의, 라벨에 명시).
