## 초기 관심 계약

`Interest`는 구매·제품 생성과 별도 UUID이며 name/identity/source_matches/note/archived_at/
nullable product_id를 갖는다. source_matches는 source UUID별 product_key(외부 제품),
external_url/external_key(원래 판매 항목)/external_name을 보존한다. ID가 없는 HTML 소스는
key null을 허용하고 실제 요청에서 host·DNS 정책을 다시 검증한다.

0016은 외부 offer/캐시에 interest_id를 추가하며 기존 product_id 또는 interest_id 하나만
가진다. 관심의 구매 전환 후에도 과거 offer/감시의 Interest.id 참조를 바꾸지 않는다.
새 관심 자료를 표현할 수 없는 구버전으로의 downgrade는 해당 신규 자료를 제거하므로
운영 자동 downgrade를 사용하지 않는다. 기존 제품/구매 참조는 보존한다.

최소 GET/POST/PATCH API는 사용자 소유권·공개 URL·수정 revision을 검증한다. 생성 요청의
request_id가 같으면 같은 관심 UUID를 돌려주며, 같은 키의 다른 입력은 충돌로 거절한다.
관심 등록만으로 구매·재고 합계가 늘지 않는다. B08은 이 계약 위에 구매 전환/목록 UX를 더한다.

검증: 관심 CRUD·반복 저장 및 0013→0016→0013→0016/drift 집중 5검사 통과.
Ruff·format·ty 검사 통과. 새 탐색 UI/서비스의 검증은 같은 문서에 이어 기록한다.

## Exa 환경 설정과 실제 확인

2026-09-07 사용자가 EXA_API_KEY 사용과 ~/.bashrc 등록을 승인했다. 다른 WSL 셸의 export는
기존 프로세스에 전달되지 않아 사용자가 직접 ~/.bashrc에 추가했다. 그 설정을 유지하고
임시 파일 로더 중복만 제거했다. ~/.bashrc 권한0600·Bash 문법·새 대화형 셸의 변수 존재를
값 노출 없이 확인했다. 개인 컨텍스트/압축 설정은 변경하지 않았다.

제공자 코드의 fast search 검증 요청 **1회 성공**, 생성형 요청0. 실제 키는 로그·Git·
스크린샷·공개 artifact에 저장하지 않았다. 이는 인증/응답 확인이며 전체 자료 수용의
완료를 뜻하지 않는다. 최종 앱의 암호화 연결 등록과 다중 도메인 탐색 검증을 이어 수행한다.

현재 [Exa Contents 공식 문서](https://exa.ai/docs/reference/get-contents)는 highlights를
LLM이 선택하는 발췌로 설명하므로 새 탐색에서는 highlights도 요청하지 않는다. 제한된
text 추출만 사용하고 summary/Answer/deep/outputSchema/systemPrompt/context를 제외한다.
검색엔진 자체의 내부 구현 전체를 비AI라고 주장하지 않는다. 공급 API가 제공한 발췌와
원문 직접 확인/재사용·보관 권리는 구분한다.
