# 웹 지침

공통 규칙은 루트 [AGENTS.md](../AGENTS.md), 검증 명령은
[development.md](../docs/development.md)를 따른다.

- 기존 Vite + React + TypeScript, TanStack Query, Dexie와 라우팅/스타일 구조를 재사용한다.
  일반 앱 화면 변경에 Next.js·ShadCN이나 새 디자인 시스템을 도입하지 않는다.
- 새 UI는 기존 컴포넌트·스타일 토큰을 먼저 확인한다. 모바일 터치·키보드 초점·레이블·
  한글 IME 입력을 보존하고 시각 변화는 합성 데이터로 실브라우저에서 확인한다.
- Dexie의 낙관적 변경, outbox 등록, 서버 응답 반영의 경계를 함께 검토한다. 재전송·
  성공 응답 유실·두 탭·계정 전환·부모/자식 순서를 관찰 가능한 흐름으로 테스트한다.
- 폼 draft와 outbox 대기는 별도 상태다. SW 업데이트·새로고침·offline cold start가
  작성 중인 입력을 잃게 하지 않는다. 지연 응답이 새 질의나 새 계정의 화면을 덮지 않게 한다.
- 앱 계산 변경은 Python과 공유하는 합성 fixture로 null/0·정밀도·반올림을 대조한다.
  관심 저장만으로 구매·재고·실구매 합계가 늘지 않게 한다.
- 외부 자료는 출처·조건·관측 시각·부분 실패·캐시 상태를 유지한다. 외부 HTML이나 URL을
  검증 없이 렌더링하지 않는다. 등록/검증/활성 상태를 하나의 성공 표시로 합치지 않는다.
- Vitest/jsdom·브라우저 API mock의 통과와 실브라우저 수용은 구분한다. UI/PWA가 바뀌면
  해당 WP의 브라우저 시나리오·환경·결과와 민감정보 없는 스크린샷 또는 로그를 남긴다.
