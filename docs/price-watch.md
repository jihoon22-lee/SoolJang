# 가격 관측·목표가·알림

가격 이력은 보관이 허용된 소스에서 실제로 조회한 관측만 보여 준다. 제품과 관심 대상의
이력을 각각 조회하며 관심 대상의 특정 판매 조건을 선택해 목표가를 만든다. 제품·판본
고정, 통화, 용량·수량, 회원·쿠폰·수령·지역·배송·세금 조건이 확인되어야 한다. 최초 관측
이전 가격이나 다른 판매 조건의 가격을 이어 붙이지 않는다.

## 사용자 선택

새 목표가는 수동 조회만 허용한다. **정기 조회 동의**와 **해당 대상의 웹 푸시 동의**는
각각 기본 꺼짐이다. 푸시는 기기별 브라우저 권한과 구독 등록도 필요하다. 화면 진입이나
목표가 저장으로 조회·브라우저 권한 요청을 시작하지 않는다. 설정 입력은 기존 계정별
임시 입력 복구를 사용하고 저장 시 revision 충돌을 확인한다.

정기 조회는 15분~7일 간격이며 새 동의 후 한 간격이 지난 뒤 시작한다. 서버 UTC 기준
발생 슬롯을 사용한다. 장기 중단 중 놓친 슬롯은 한 번으로 합쳐 재시작 시 요청 폭증을
막는다. 일시 중지·해제, 관심 보관, 고정 해제, 소스/연결 중지, 필수 인증 정보 부재,
가격 이력 보관 미허용은 실행을 막는다. 기존 관심·가격 이력·알림은 보존한다.

새로 저장한 완전한 성공 관측 중 고정된 상품의 동일한 판매 조건만 목표가와 비교한다.
캐시·last-good·부분 결과·미확정 판본·품절·재고 미확인·오래된 가격·미확인 조건은 알리지
않는다. 가격 유효 시간은 1분~24시간이다. 동일 가격의 반복 알림을 억제하고 목표가
재진입 또는 직전 알림보다 추가 하락 시에도 최소 재알림 간격 15분~7일을 적용한다.
앱 내 알림은 푸시 동의 없이도 남는다.

## 실행·복구 계약

- `PriceWatchRun`은 발생 키를 고유하게 저장한다. 동일 수동 요청 ID 재전송과 같은 UTC
  일정 슬롯은 한 작업이다. 여러 프로세스의 scheduler/worker는 DB 잠금과 임대 토큰으로
  소유자를 정한다. 조회 임대는 120초, 최대 3회 시도다.
- 조회 전 각 outbound 경계와 결과 저장 전 활성 상태·revision·임대 토큰을 다시 읽는다.
  설정 변경은 대기/실행 중 작업을 취소한다. 상태 변경과 결과 처리는 감시→작업 순서로
  잠가 교착을 피한다. 이미 전달된 외부 요청 자체를 취소했다고 표시하지 않는다.
- 알림은 감시·관측 ID 조합, 전송은 알림·구독 조합에 고유성을 적용한다. 알림 생성과
  전송 대기 저장은 같은 트랜잭션이다. 사용자당 활성 감시 100개, 유효 구독 5개,
  전송 대기/진행 500개까지다. 초과 시 앱 내 알림과 `queue_full` 상태를 남긴다.
- 전송 의도를 먼저 `sending`으로 커밋하고 HTTP를 시작한다. 임대 30초 이후 남은
  `sending`과 응답을 확인할 수 없는 전송은 `unknown`으로 끝내며 자동 재전송하지 않는다.
  429/503의 명시적 일시 거절만 60~3600초 뒤 최대 3회 재시도한다. 404/410은 구독을
  만료시킨다. 한 시간 지난 대기는 취소한다. 외부 접수 성공은 실제 화면 표시 성공과 다르다.
- 작업 원장·알림·전송 상태와 암호화한 구독은 PostgreSQL 백업 대상이다. 복구 후
  불확실한 전송을 새 대기로 돌리지 않는다. 완료된 원장/앱 내 알림의 자동 삭제는 없으며
  UI는 최근 100개를 읽는다. 이력 보관 정책은 [소스 정책](plans/v1.7.0/sources.md)을 따른다.

## 웹 푸시와 운영 설정

`SOOLJANG_PRICE_WATCH_WORKER_ENABLED`가 실행을 제어한다(기본 켜짐, 테스트 환경은
자동 기동 제외). 별도 서비스 없이 API lifespan에서 15초 주기로 실행하며, 여러 API
프로세스도 DB 원장으로 경합을 조정한다. `/ready`는 실행 task와 120초 이내 heartbeat를
확인한다. 설정이 꺼지면 수동 실행 API도 거절하며 저장된 목표가는 보존한다.

`SOOLJANG_PUSH_VAPID_PRIVATE_KEY`는 P-256 개인 스칼라 32바이트의 base64url 표현,
`SOOLJANG_PUSH_VAPID_SUBJECT`는 운영 연락처 `mailto:` 또는 HTTPS URL이다. 배포 비밀로
주입하며 API는 공개키와 준비 여부만 반환한다. 개인키를 저장소에 넣지 않는다. 키 교체 시
기존 구독은 전송 대상에서 제외하고 사용자가 브라우저 구독을 갱신한다.
`SOOLJANG_PUSH_ALLOWED_HOSTS`는 기본 Google FCM·Mozilla·Apple push host 목록을
대체하는 쉼표 구분 설정이다. HTTPS와 공개 연결 대상 검증을 통과해야 하며 redirect와
자동 HTTP 재시도는 사용하지 않는다.

구독 endpoint·수신 키는 기존 마스터 키로 암호화한다. API 목록에는 fingerprint·상태만
노출하며 요청 URL·본문·개인키를 로그에 남기지 않는다. 해제/만료 시 암호문을 제거하고
복호화 실패는 암호문을 보존한다. 로그아웃은 현재 브라우저 구독도 종료한다.

전송 본문은 이벤트 UUID만 포함한다. 제품명·가격·구매/음주 기록은 잠금 화면에 넣지
않는다. Service Worker는 일반 알림을 표시하고 고정된 동일 origin 가격 감시 화면으로
이동한다. 이벤트 ID 중복 기록은 최대 500개/30일이다. 표시 전에 기록하므로 종료 사고
때 표시를 놓칠 수 있으며 이는 중복 표시를 줄이기 위한 선택이다. 서버 접수·브라우저
표시의 exactly-once를 보장하지 않는다.

암호화는 `http-ece`의 aes128gcm과 기존 `cryptography`를 사용한다. 표준 근거는
[RFC 8291](https://www.rfc-editor.org/rfc/rfc8291.html),
[RFC 8292](https://www.rfc-editor.org/rfc/rfc8292.html)이다.
실행 증거와 미실행 범위는 [B07 workthrough](../workthrough/2026-09-07-v170-b07-price-watch.md)에 둔다.
