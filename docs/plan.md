### 저장 완료 후 새 시음·관심 연속 저장

PR #168의 [시음 날짜 리뷰](https://github.com/jihoon22-lee/SoolJang/pull/168#discussion_r4241539039)와
[관심 링크 리뷰](https://github.com/jihoon22-lee/SoolJang/pull/168#discussion_r4241539059)를
최신 main에서 재현했다. 후속 #170은 시음 수정폼, #171은 문서 변경이므로 두 결함은 남아 있었다.
Q02/Q06의 QS03/QS05/QS13/QS17/QS18/QS19 관련 수정이다.

- 성공한 시음은 제출한 초안을 버전 확인 후 지우고, 새 폼 기본값은 저장하지 않는다.
  다음 날 다시 열면 오늘 날짜를 사용하며 작성 중·실패한 초안은 선택 날짜를 보존한다.
- 관심 전체 교체 요청은 마지막 성공 응답의 목록·출처·revision을 함께 사용한다.
  느린/실패한 refetch와 연속 저장에서도 기존 링크를 보존하며 동시 변경은 409로 보호한다.

## 3. 공통 계약과 결정

- **D261 간결한 화면 원칙:** 기록은 짧게(빠른 시음은 타이핑 없이 4탭, 재구매 핵심 입력 5칸), 확인은 한눈에(목록 한 행 2~3줄, 홈 1.5화면 이내), 관리는 한 단계 뒤(정정·이력·계산 기준은 행 상세·접힘·메뉴). 보호 동작은 지우지 않고 위치와 문구만 바꾼다. 계산식·외부 요청 상한 같은 시스템 설명은 화면 본문에 두지 않는다.
- **D262 시각:** Cellar Dark 팔레트·토큰을 유지한다. 브라스는 주 버튼과 현재 상태에만 쓰고 내부 제품/주종 이동 이름은 어디서나 본문색·무밑줄(D240 전면 적용)이다. 하단 탭은 아이콘+라벨과 가벼운 활성 표시, 숫자는 자리 맞춤, 목록은 카드 안 카드 대신 구분선을 쓴다. 병 잔량 게이지는 장식이 아닌 정보 요소이며 잔량 미기록을 빈 병으로 그리지 않는다(D242).
- **D263 목록:** 모바일 검색창은 접지 않는다. 한 행은 이름·재고 / 주종·용량·판본 / 평단가·100ml당(정가, D68)·내 평점 세 줄이며, 구매 조건 필터가 있으면 가격 줄을 조건 평균 정가·실구매가·조건 100ml당으로 바꾼다. 규격이 둘 이상이면 규격 칩으로 규격별 재고·실평단가와 규격 이동(R01·R02)을 유지한다. 데스크톱 표는 내부 스크롤 없이 페이지가 스크롤하고 머리글은 실제 앱 헤더 높이 아래에 붙는다. 표가 결과 영역보다 넓으면(좁은 데스크톱·조건 열) 페이지 대신 표 안에서만 가로로 넘긴다.
- **D264 구매 참조:** 사람이 읽는 맥락(용량·구매일·구매처)이 같은 구매가 둘 이상일 때만 "구매 …" 참조를 덧붙인다. 저장·선택·라우팅은 언제나 원 UUID를 쓴다. 병 번호는 구매마다 1부터라, 병을 고르는 곳(빠른 시음 병 고르기·홈 열린 병·상세 머리부)은 같은 이름·용량으로 보이는 병이 둘 이상일 때만 번호를, 번호까지 같으면 "구매 날짜 · 구매처"를 덧붙인다. 상세 머리부는 규격이 둘 이상이면 용량도 보인다.
- **D265 홈:** 마신 술·산 술 기록 두 행동, 현재/미개봉/개봉·재고 원가 한 줄, 열린 병(잔량 게이지와 바로 한 잔 기록), 최근 시음만 둔다. 주종별 보유(병 목록 이동 포함)와 랭킹은 통계, 관리 화면 바로가기는 설정 메뉴로 옮긴다.
- **D266 통계:** 첫 화면은 기간 칩과 요약이다. 주종·상태 필터는 접힌 영역에 두되 적용 중이면 요약으로 보인다. 일반 계산 기준 문단은 한 곳으로 모으고 표본·제외 수와 근거 이동은 해당 수치 옆에 남긴다(D246 유지). 인사이트 밖 탭(상세 합계·주종별·랭킹)은 기간 필터와 별개인 전체 기록이므로 탭 위에 "전체 기간 기준 · 구매 N건(0원 M건 포함)"을, 평균 할인율 옆에 정가 기록 수를 둔다.
- **D267 빠른 시음:** 저장이 끝나면 시트를 닫고 토스트로 "고치기·한 잔 더·보기"를 제공한다(Q02·QS05의 연속 행동 유지). 결과 미확정·실패는 지금처럼 시트 안에서 처리하고 초안 정리 규칙(D248)과 재전송(D249·D255)은 바꾸지 않는다. 이어가기 토스트는 홈이 띄우고 거둔다(화면을 떠나거나 새 기록을 열면 닫음). 단추에 포인터·초점이 있는 동안은 닫히지 않고, 병을 비운 기록에는 "한 잔 더"가 없다.
- **D268 등록·상세:** 새 술 폼은 이름·주종·용량·도수와 구매 칸을 먼저, 나머지는 "더 입력"에 둔다. 평점은 어디서나 별 입력(6점·0.5 단위·0점과 미평가 구분)이다. 이미 있는 이름이면 그 술의 구매 추가로 안내한다. 상세 머리부는 잔량·주 행동(한 잔 기록·구매 추가)과 제품 평점·시음 평균을 이름을 나눠 보이고, 최근 시음을 펼침 없이 병 구역에 둔다(D253 순서 유지). 제품 평점은 DB·API 계약 (0, 6]이라 0점이 없고 미평가는 "평점 없음"(null)이다. "한 잔 기록"은 상세 병 구역의 병 시음 입력을 쓰고 빠른 시음 시트를 겹쳐 열지 않으며, "구매 추가"는 온라인에서만 보인다. 다른 화면에서 건너온 정정·구매 추가 폼은 늦게 불러온 목록에 밀리지 않게 잠시 자리를 지키고 사용자 입력이 있으면 바로 놓는다. 머리부 시음 평균은 시음 이력 요약 값(Decimal 짝수 반올림, 서버와 같음)을 그대로 쓴다. 구매 추가 폼의 제출은 "구매 저장"이라 여는 단추와 이름이 겹치지 않는다. 정정 폼을 닫으면 연 단추나 그 시음 행으로 초점을 돌린다. "산 술 기록"·"이 술에 구매 추가"는 한 번 쓰는 진입 표시라 받으면 경로에서 지운다.

- **D269 v1.12.0 릴리스·배포:** U1~U6 화면 개편을 MINOR로 게시하고 schema 0021을 유지한다. API는 버전 문자열과 dnspython(CVE 수정)만 바뀐다. 태그 전 백업·격리 복원·조회 대조에 더해 전환 직전 새 백업을 빈 DB에 복원하고 새 API 이미지로 조회를 대조하며 운영과 복원본의 전체 행 해시를 UTC·READ ONLY로 비교한 뒤 API → 웹 순으로 고정 이미지를 전환한다. 웹만 바뀌므로 1.11.1 클라이언트가 남긴 초안·outbox·보기 상태 형식이 그대로임을 확인한다. 복귀는 같은 schema의 v1.11.1 이미지로 하며 그 이미지를 지우지 않는다.
- **D260 v1.11.1 릴리스·배포:** F1~F5 결함 수정은 PATCH로 게시하고 schema 0021을 유지한다. 사용자 승인의 Push·PR·Release 뒤 추가 운영 배포 요청을 받아 같은 태그의 검증된 이미지로 전환한다. 태그 전과 전환 직전의 백업·격리 복원·새 코드 조회 대조, Release CI·GHCR 게시와 실제 운영 상태를 각각 기록한다. 전체 데이터 해시는 DB 연결의 시간대를 UTC로 맞춰 비교하며, DB·uploads와 기존 암호문을 유지한다.
- **D259 제출 보안 감사:** F1 CI에서 발견한 Vite·Vitest·certifi advisory는 기존 범위의 패치 버전과 lockfile만 갱신한다. 새 외부 제공자·키·수집을 추가하지 않으며 도구·인증서 묶음 패치를 별도 커밋으로 보존한다. npm/pip 감사와 해당 경계 회귀를 거쳐 모든 후속 PR에 통합한다.
- **D254 기록 보존:** 구매 축소는 활성 시음이 없는 미개봉 병만 큰 번호부터 제거한다. 부족하면 구매·병·이력 전체를 변경하지 않고 409로 거절한다. 삭제된 시음의 원본은 보존하고 부모 삭제 뒤 복구는 기존 휴지통 규칙을 따른다. 다른 키의 소진·증여·판매 재전이는 종료 상태를 덮지 않으며 같은 키 재전송은 기존 영수증을 반환한다.
- **D255 생성 재개:** 온라인 생성이 부분 성공하거나 결과 미확정이면 같은 탭·계정에서 새 오프라인 생성으로 우회하지 않는다. 성공 단계·요청 키를 유지해 재개하고 제출한 초안·폼 인스턴스만 정리한다. 이전 완료가 새 초안을 지우거나 같은 입력을 다시 신규 생성하게 하지 않는다. 제품 생성의 확정 409는 자동 재전송을 멈추고 목록 확인·명시적 중단을 제공한다. 중단 자체로 서버 기록을 지우거나 새로 생성하지 않으며 미확정 네트워크 실패와 구분한다. 전송 전 거절·최초 확정 422는 복구 상태와 임시 사진만 정리한다. 초안·요청 키는 유지하며, 남은 키만으로 전송 복구 상태를 새로 만들지 않는다.
- **D256 계층 변경:** 순환·깊이·소유권 검사는 사용자 쓰기 잠금을 얻은 뒤 최신 계층으로 수행한다. 주종 변경과 제품 주종 배정의 잠금 순서를 맞춰 삭제된 주종으로 새 연결이 생기지 않게 한다.
- **D257 인증 동시성:** 인증 세대가 달라진 응답은 현재 계정의 세션·캐시를 변경하지 않는다. 활동 시각은 인증 유효성 검사와 구분한 제한된 별도 갱신이며 업무 트랜잭션의 응답 전 commit 경계를 유지한다.
- **D258 외부 평점:** 원척도에서 유효하지 않거나 계산할 수 없는 평점은 정규화 값을 누락 처리한다. 0점·정상 척도·출처를 보존하며 잘못된 값을 0점 또는 만점으로 생성하지 않는다.

- **D240 표시:** 내부 제품/주종 이동은 본문색과 무밑줄을 사용하며 버튼 의미·포커스·44px 터치 목표를 보존한다. 외부 출처 링크와 구분한다. 기존 Cellar Dark 토큰과 본문 글꼴을 재사용한다.
- **D241 시음 생명주기:** 수정은 ID·첨부를 보존한다. 삭제/복구는 조회 버전·계정·멱등 요청을 검증하고 관련 목록·Dexie를 갱신한다. 삭제는 D67에 따라 현재 잔량을 자동 복원하지 않는다. 복구도 기록만 복구한다. 현재 잔량 정정은 별도 명시적 최종값으로 처리한다.
- **D242 재고:** 현재 보유=미개봉+개봉. 제품 종류 수·누적 구매·소진·증여·판매는 별도 값이다. 상위 주종은 후손을 포함하고 하위 행과 다시 합산하지 않는다. 잔량 미기록은 0ml가 아니다.
- **D243 관심:** identity 편집은 전체 식별정보를 보존한다. 식별 변경 후 기존 고정·감시는 재확인한다. 소프트 삭제/복구는 구매·병·가격 관측·전환 영수증을 보존하고 감시는 자동 재개하지 않는다. 선택 출처 URL만 저장하고 검색 본문/발췌는 저장하지 않는다.
- **D244 검색:** 표시명·원어명·사용자 확인 별칭을 구분한다. 출처를 확인한 작은 브랜드 사전으로 한영 질의를 연결하며 빈티지·숙성·배치·용량·세트 조건을 버리지 않는다. 별칭은 제품 자동 병합·고정의 근거가 아니다. 서버·오프라인 동일 정규화·초성 규칙과 평가 자료를 사용한다.
- **D245 탐색:** 응답 도착 순서와 최종 순위를 분리한다. 원순위·질의·언어·출처를 남기고 동일 URL과 동일 제품을 구분한다. 모르는 속성/평점/가격은 생성하지 않는다. 기존 호출 상한·취소·부분 실패·no-store·allow_llm=False·출처별 권한을 유지한다.
- **D246 통계:** 관측 사실→비교 기준/표본→근거 기록→다음 행동을 제공한다. 제품 평점과 시음 평점, 같은 SKU의 가격 조건, 0원과 미기록, 현재 재고와 날짜가 있는 이벤트를 구분한다. 날짜 없는 과거 재고 추이·음용 안전 기한·자동 취향 인과 설명은 생성하지 않는다. 파생 지표를 DB에 저장하지 않는다.
- **D247 시음 정정 안전성:** 일반 저장은 평점·메모만 부분 변경한다. 고급 변경은 표시·이번 편집 확인 후 별도 적용하며 Enter 암시 제출을 막는다. 보관과 폐기를 구분하고 결과 미확정은 원요청만 재확인한다. 충돌 복구도 실제 제출 범위로 확인한다.
- **D249 쓰기 확정:** 사용자 쓰기 응답은 DB commit 이후에만 성공으로 보낸다. 온라인 제품·구매 생성은 단계별 `request_id`(탭·계정 범위)를 결과가 확정될 때까지(성공 또는 409) 유지해 같은 행을 다시 돌려주고, 처음 요청 지문(`outbox_receipt`)과 내용이 하나라도 다르면 409로 앞선 저장을 알린다(만든 뒤 수정과 무관). 연결 실패·5xx·422·401은 키를 유지한다. 보내지 않은 수정 뒤의 오프라인 수정은 마지막 서버 확인 버전을 기준으로 삼는다. 이미 서버에 있는 행의 실패한 수정·동작을 폐기할 때는 그 결과에 이어진 명령만 함께 폐기한다.
- **D250 기록 연결 보존:** 시음이 붙은 병이 있는 구매 건은 온라인·동기화 모두 삭제를 거부한다(병만 지우면 시음이 고아가 된다). 늦게 도착한 오프라인 시음은 소진·증여·판매된 병의 상태·날짜·잔량을 바꾸지 않고 기록만 연결한다. 개봉 잔량은 0 초과·용량 이하다. 최근 30일 삭제 시음 중 제품·병이 살아 있는 기록만 "최근 삭제한 시음"에서 복구한다(잔량 불변, 쪽 단위로 30일 안의 기록 전부를 이어 읽는다). 휴지통은 시음만 다루며 구매·병 복구는 범위 밖이다.
- **D251 경계 신뢰:** 앱은 nginx가 덮어쓴 `X-Real-IP`(앞단 X-Forwarded-For의 마지막 홉)만 클라이언트 주소로 쓰고, 운영 쿠키는 항상 Secure다. 보안 헤더·CSP는 모든 정적 응답에 붙인다. 외부 응답의 무한·거대 수치와 깨진 소스 명세는 500이 아니라 누락·설정 오류로 끝낸다.
- **D248 저장 경계:** 완료한 시음의 새 기본값은 초안으로 저장하지 않는다. 작성 중 초안은 날짜 경계를 넘어 보존한다. 관심 목록 전체 교체에는 동일한 성공 응답의 값과 revision을 함께 사용하며 다른 작성자의 변경은 충돌로 보호한다.
- **D253 화면 보조 상태:** 통계·인사이트 보기 상태는 계정별 탭 세션에만 둔다. 제품 상세는 탭으로 숨기지 않고 병·시음을 구매보다 먼저 두며, 정정·근거 이동이 가리키는 구역을 지운 채 보이지 않게 하지 않는다. 매장 모드 관심 저장본은 계정 DB `sync_meta`의 읽기 전용 사본으로 쓰기·감시 판단에 쓰지 않는다. 외화 구매의 원화 실구매가는 외화 단가 × 환율과 1% 안에서만 받는다(구매 금액·분할 조각은 Numeric(14,2), 환율은 Numeric(14,6)에 반올림해 담기는 값만). 관심 비교의 관측가는 그 관심에 고정한 출처 제품의 관측으로만 계산한다. 한글 별칭 앞부분 검색은 질의 끝 두 글자 이상만 채운다(서버·웹 같은 표)
- **D252 수용·배포:** 자동 검사·합성 브라우저·실연결·복구·실사용자 평가·운영 확인을 구분한다. 실제 실행하지 않은 범위를 통과라고 쓰지 않는다. 배포 전 백업과 격리 복원, 배포 후 정확한 이미지/버전/스키마·기록 보존·화면 경로를 확인한다.

디자인은 기존 그린블랙 `#131f1a`, 패널 `#1b2b24`, 본문 `#ece4d3`, 보조 `#a9b3a6`,
브라스 `#c99a4a`를 유지한다. 이름·읽기 순서·정렬된 수치에 위계를 주고, 반복 입력폼을
접힌 편집 영역으로 옮긴다. 360px에서는 이름·상태 다음 줄에 규격/동작을 배치한다.
단순 장식·새 프레임워크를 추가하지 않고 실제 관리 과업의 동작·오류 회복을 디자인 기준으로 삼는다.
