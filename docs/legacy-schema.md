# 레거시 엑셀 스키마 실측 분석

기존 관리 수단인 엑셀 시트를 실제로 파싱해 확인한 사실만 기록한다. 추측은 "가설"로 명시하고,
검증한 것은 검증 방법과 결과를 함께 남긴다. 이 문서는 **Task 6(블록 분리 파서)과
Task 11(임포터)의 유일한 사양 근거**다.

- 원본: `/mnt/e/alcohol.xlsx` (142,118 bytes)
- 분석 대상: 같은 시트를 CSV로 내보낸 `/mnt/e/alcohol.csv`
- 분석 일자: 2026-07-31
- 두 파일 모두 저장소에 커밋하지 않는다 (개인 소비 기록)

## 1. 인코딩과 문자 처리

| 항목 | 실측 결과 |
|---|---|
| 인코딩 | **CP949** (한국어 Windows ANSI). `file` 판정은 "CSV ISO-8859 text"로 부정확 |
| 원화 기호 | `₩`가 **`\` (0x5C)** 로 저장됨. CP949에서 원화 기호와 백슬래시가 같은 코드포인트 |
| 금액 형식 | `" \23,980 "` — 앞뒤 공백 + `\` + 천 단위 쉼표 |
| 무가격 표기 | `" \- "` — 선물 등 가격이 없는 경우. NULL로 처리 |
| 셀 내 개행 | 다수 컬럼에 존재. CSV quoted field 안에 raw `\n` |

읽기: `path.read_bytes().decode("cp949")` 후 `csv.reader`. `iconv -f CP949 -t UTF-8`도 동작한다.

금액 정규화: `\`, `,`, `₩`, 공백 제거 → `-`이면 NULL → 그 외 숫자로 변환.

### 블록 판별 규칙 (Task 6 구현 사양)

본 테이블 데이터 행의 판별 조건을 모두 만족해야 한다.

1. 컬럼 수가 20이다
2. `이름`(index 0)이 비어 있지 않다 — 합계행(432)과 랭킹 소계행을 배제한다
3. `구매`·`소비`·`재고`·`미개봉`·`개봉`(index 10–14)이 모두 정수다

빈 행을 만나면 **종료하지 않고 건너뛴다**. 위 조건을 만족하지 않는 행이 나오면 본 테이블
구간이 끝난 것으로 보고 이후는 통계 블록으로 간주해 버린다.

단순 조건만으로는 464–476 구간(우측 주종 롤업 매트릭스가 index 10–14에 정수를 가짐)이
오탐된다. `이름` 컬럼이 비어 있거나 `병당 가격 상위 10위 술` 같은 제목 문자열이라는 점으로
배제되지만, **회귀 테스트로 이 구간이 데이터로 잡히지 않는지 반드시 확인**한다.

### 4.2 금액 컬럼의 의미 (초기 가정이 틀렸음 — 검증으로 정정)

`가격`과 `실구매가`는 **병당 단가가 아니라 해당 술의 총액**이다.

| 컬럼 | 의미 | 검증 |
|---|---|---|
| `가격` | 정가 기준 **총액** (병당 정가 × 구매 병수) | 429행 단순합 `42,401,108` ≈ 합계행 `42,401,100` |
| `실구매가` | 할인·쿠폰 적용 후 **총 지불액** | 단순합 `36,495,454` ≈ 합계행 `36,495,447` |
| `평단가` | `가격 ÷ 구매 병수` | **391건 일치, 불일치 0** |
| `실평단가` | `실구매가 ÷ 구매 병수` | 동일 규칙 |
| `100ml당 가격` | **`평단가 ÷ (용량 ÷ 100)`** — 정가 기준 | **391건 일치, 불일치 0** |

`100ml당 가격`을 실평단가 기준으로 계산하면 186건만 일치하고 168건이 불일치한다(예: 글렌고인
25y — 평단가 848,000 / 700ml → 엑셀 값 `154,286`이 정가 기준과 일치). 따라서 **정가 기준이
확정**이다. 통계 재현(Task 14) 시 이 기준을 따른다.

합계행과 8원·7원 차이가 나는 것은 엑셀 셀 서식이 원 단위 미만을 절삭해 표시하기 때문이다.
임포터는 **총액을 원본으로 신뢰하고 병당 단가·단위 가격은 재계산**한다.

`용량 × 구매 병수` 합계는 **704,970ml로 합계행과 정확히 일치**한다. `용량`은 병당 용량이다.

### 4.6 구매처 컬럼 — 엑셀 한계의 직접적 증거

같은 술을 여러 곳에서 산 경우를 한 셀에 개행으로 몰아넣었고, 형식이 일정하지 않다.

```
이마트 수원점 / 와인픽스 동탄점                      (구매처만)
레투와(9.1) / 스타보틀 인계(6.8)                     (괄호 안은 만원 단위 가격)
스타보틀 인계 * 3 / 스타보틀 인계 * 1 / 라빈리쿼 ... * 1  (별표 뒤 병수)
이마트 스마트오더 1 / 트레이더스 수원점 2             (뒤 숫자가 병수)
```

형식이 통일되지 않아 완전 자동 분해는 불가능하다. 임포트 정책:

1. 개행으로 분할해 **여러 구매 건 후보**를 만든다
2. 병수 힌트(`* N`, 뒤따르는 정수)를 파싱하되 총합이 `구매` 컬럼과 맞지 않으면 분할을 포기하고
   단일 구매 건으로 적재한다
3. 원문을 `purchase.import_note`에 그대로 보존하고, 분할이 필요한 행을 리포트에 표시해
   사용자가 UI에서 나중에 쪼갤 수 있게 한다

고유 구매처는 개행 분할 후 **82개**다. 예: `시윤이네`(39), `테라브루`(32),
`이마트 스마트오더`(29), `코스트코 양평점`(28), `고래맥주창고 신동점`(25),
`트레이더스 수원점`(22), `와인백`(21), `데일리샷`(20), `GS25 와인25+`(16),
`카카오톡 선물하기`, `회사선물`, `신라 온라인 면세`, `2024 수원 메가쇼` 등.

### 4.7 외부 평점 컬럼 — 소스별 다중 평점

단순 숫자가 아니라 `값 (소스태그)` 형식이며, 한 셀에 여러 소스가 개행으로 들어 있다.

```
3.39 (RB)
3.40 (RB) ⏎ 3.96/89 (BA) ⏎ 3.578 (U)
3.9                                    (태그 없음)
```

| 태그 | 소스 | 건수 |
|---|---|---|
| (없음) | Vivino 등 (주종 문맥으로 추정) | 107 |
| `RB` | RateBeer | 28 |
| `U` | Untappd | 19 |
| `BA` | BeerAdvocate (`4.06/91` 처럼 5점/100점 병기) | 18 |

→ 소스마다 스케일이 달라 단일 컬럼으로는 표현할 수 없다. `external_rating` 테이블에
**소스·값·스케일**을 분리 저장하는 설계의 직접적 근거다. 임포터는 이 패턴을 파싱해 소스별
레코드로 분해하고, 태그를 소스 레지스트리에 매핑한다.

## 6. 엑셀에서 소실되는 정보 (이 프로젝트가 해결할 것)

1. **구매 건별 이력**: 한 행에 병수만 집계되어, 서로 다른 시점·구매처·가격의 구매가 하나로
   합쳐진다. 28행은 개행으로 억지로 표현했지만 형식이 깨져 있다
2. **구매 일자**: 컬럼 자체가 없다. 비고의 `26년 4월 이마트 주류위크` 같은 문자열이 유일한 단서
3. **개별 병 상태**: 미개봉·개봉 병수만 있고 어느 병이 언제 개봉되었는지 알 수 없다
4. **시음 이력**: `느낀 점` 한 칸뿐이라 같은 술을 여러 번 마신 인상 변화를 기록할 수 없다
5. **외부 평점 출처**: 소스 태그는 있으나 조회 일자·URL이 없어 재확인이 불가능하다

임포트는 행당 **합성 구매 건(synthetic purchase lot) 1개**를 만들고, 구매 일자는 NULL로 두며,
`느낀 점`은 시음 세션이 아닌 제품 노트로 이관한다. 이후 사용자가 UI에서 구매 건을 분할하고
병 단위 기록을 시작한다.
