## 데이터 소유와 식별

| 개념 | ID·소유자 | 보존할 의미 / 후속 소유 WP |
|---|---|---|
| 제공자 연결 | 사용자별 stable UUID, provider kind | credential 등록/검증/활성 분리, 키 교체 시 revision 증가; WP05 |
| 외부 소스 | 기존 `external_source.id/user_id` | 연결과 원문 도메인/자료 역할은 별개, 사용자 override 보존; WP04/05 |
| 원문 자료 | 원문 URL + 출처 + 조회/작성 시각 | 검색 발췌/허용 원문/공식 자료 구분, 개별 표시/보관 정책 적용; WP08 |
| 외부 제품 매칭 | 기존 제품/SKU 및 `external_product_match` | canonical 판본 식별자와 출처별 상품 ID 연결, 사용자 확정 고정 보존; WP06 |
| 판매 조건 | 출처·상품·판매자·판본·규격·수량·조건 | 같은 상품의 복수 판매자를 하나로 합치지 않음; WP07 |
| 가격 관측 | 판매 조건 + 실제 관측 시각 | 원통화/가격/null/조건/출처, 캐시 사용 시 새 관측 생성 금지; WP07/10 |
| 관심 대상 | 사용자별 stable UUID | 비보유 제품도 저장, 감시와 동일 ID 사용, 구매/재고 합계와 분리; WP09/10/12 |

`domain/discovery.py`의 `OfferIdentity`, `PriceObservation`은 가격·규격·관측 시각의 최소
검증 계약이다. source별 ID만으로 다른 출처의 상품을 자동 동일시하지 않는다. `variant_key`는
상위 제품 매칭이 확정한 canonical 판본 ID이며 비교에는 알려진 용량·판매 수량·조건도 같아야 한다.
관측 가격과 기존 실구매 가격은 서로 덮어쓰지 않는다. 모르는 판매자/규격은 임의 값으로 채워
비교하지 않고 확인 필요로 남긴다. 실제 영속 모델/API는 해당 WP의 migration과 함께 도입한다.

## 요청 경계와 사용량 (B01 구현)

- SafeHttpClient는 HTTP(S) 기본 port, userinfo 없는 URL, 등록된 정확한 hostname만 허용한다.
  base URL·정적 search URL·명시 `allowed_hosts`가 허용 범위이며 원격 후보로 범위를 넓히지 않는다.
- 모든 DNS 답이 public인지 확인하고 검증된 IP에 직접 접속한다. TLS/Host/SNI는 원래
  hostname으로 검증한다. 환경 proxy와 자동 cookie 재생을 사용하지 않는다.
- robots·검색·상세·redirect·retry 각각에 검증을 적용한다. robots 404는 규칙 없음,
  인증 오류/429/5xx/네트워크 실패는 성공으로 캐시하지 않는다. robots 허용은 원문 권리의 대체물이 아니다.
- 비밀 헤더는 HTTPS 검색 요청의 지정 host만 받는다. robots·상세·redirect에는 전파하지 않는다.
  URL/오류/필드 반사로 비밀을 돌려보내는 응답도 저장하지 않는다. 원문 excerpt는 선택한 공개 scalar
  필드만 담으며 임의 HTML/전체 JSON을 그대로 저장하지 않는다.
- HTTP 기본 상한: 요청 body 100 kB, 응답 압축 전후 각각 2 MB, hop 3, GET/HEAD retry 1,
  Retry-After 최대 2초, 요청 전체 15초/개별 I/O 5초. adapter의 질의 확장은 전체 20초·12요청 이하다.
  POST 본문은 redirect/retry로 자동 재전송하지 않는다. worker별 실제 송신 동시성은 4다.
- `external_request_usage`는 `(user, source 또는 connection, UTC minute/day)`별 예약 수를
  별도 트랜잭션에 저장한다. 공유 연결과 소스의 예약은 원자적으로 처리하고 잠금 순서를 고정한다.
  연결 모델/UI 완성은 WP05가 담당하며 이 카운터는 연결 UUID 계약을 먼저 지원한다.
- 각 네트워크 시도 직전 예약하므로 주 작업 롤백·재시작에도 유지된다. 송신 직전 중단된 예약은
  보수적으로 유지한다. UI의 **요청 예약 수는 제공자 과금/잔액이 아니다**. 캐시는 예약을 소비하지 않는다.
  source 기본 한도는 분당 6/UTC 하루 1000이며 사용자가 조정할 수 있다. minute 집계 30일,
  day 집계 366일 이후 같은 범위의 일별 첫 예약에서 정리한다. 질의나 개인 소비 기록은 저장하지 않는다.

## 상태·revision·캐시 (B01 구현)

`SourceOutcome`은 success/empty/partial, authentication_failed/forbidden/rate_limited,
network_error/parse_error/policy_blocked/invalid_configuration/credential_unavailable/unknown을
구분한다. 연결 테스트 HTTP 200과 실제 후보/자료 추출 성공은 다르다.

`external_source.config_revision`은 설정/키 갱신 시 증가하고 probe/캐시도 해당 revision을
기록한다. 이전 성공 시각은 보존하되 현재 revision과 다르면 미확인·재검증 필요로 표시한다.
기존 probe는 migration에서 revision 0/unknown으로 이전해 현재 정상이라고 추정하지 않는다.
cache snapshot v3 이전이나 source revision이 다른 캐시는 재조회한다. 실패는 성공 캐시에 쓰지 않는다.

기존 `external_source_credential`·`llm_setting`의 암호문은 변경/초기화하지 않는다. 빈 키 입력은
유지하며 복호화 실패는 해당 소스의 제한 상태로 처리한다. 통합 연결로의 실제 이전·명시 삭제는 WP05,
사용자 확정 매칭 이전은 WP06, 별도 마스터 키·전체 복구는 WP03이 책임진다.

## 소스 정책과 기능 경계

현재 확인한 후보/정책/접근 상태는 [소스 원장](../plans/v1.7.0/sources.md)을 따른다.
NAVER 신규 검색은 NCP API HUB와 legacy 인증을 구분하며 종료된 쇼핑 상품 API를 지원한다고
표시하지 않는다. API HUB Shopping Insight는 판매 가격 API가 아니다.
Brave의 저장 권리·원문 저작권, Exa 비생성 옵션, 데일리샷/키햐 게시물 재사용 조건,
Whiskybase/Untappd 계약/보관 제약을 실제 연결별로 확인한다.

v1.7.0 신규 탐색은 생성형 답변·요약·LLM 호출 없이 동작해야 한다. 기존 OCR/선택형
LLM 설정은 보존하되 신규 탐색이 요구하거나 자동 활성화하지 않는다. 소스 실패는 다른 소스를
막지 않으며 미검증·제한·검색 발견만 상태를 정상 실연결이나 신규 가격 관측으로 승격하지 않는다.

## 수용과 측정

[평가 기준선](../plans/v1.7.0/baseline.md)과 합성 fixture revision을 고정한다. 자동 동일 판정
정확도·후보 회수율·추출률은 별도로 보고하고 모두 확인 필요로 바꿔 정확도를 높였다고 주장하지 않는다.
키 등록/실연결·브라우저·복구·최종 source/image/schema 수용은 각 담당 WP의 실제 증거를 연결한다.
