# 마일스톤 작업 이어가기

경로는 저장소 루트 기준이다. `docs/plan.md` §1에서 현재 마일스톤과 진행 중 작업을 찾고,
연결된 메인 계획·수용 명세·담당 WP를 읽는다. 과거 Task 전체나 무관한 스킬은 읽지 않는다.

1. `git status --short --branch`, HEAD, 원격 main, 열린 PR을 읽어 이미 완료된 변경과
   현재 작업을 대조한다. 미커밋 변경을 보존하고 기존 PR 작업이면 해당 브랜치를 재사용한다.
   GitHub 연결 도구를 사용하되 지원하지 않는 조회는 인증된 `gh`로 수행할 수 있다.
2. 담당 요구사항(R)/시나리오(S), 선행 계약, 실제 PR 묶음, 이번 비범위를 짧게 정리한다.
   N:M 매핑을 따르고 단순히 이슈·파일이 많다는 이유로 PR을 늘리지 않는다.
3. 수정 대상 하위 `AGENTS.md`, 관련 코드·fixture·설계만 읽어 구현한다. 필요한 최소
   계약부터 진행하고 모든 후보 소스의 조사 완료를 후속 작업의 선행 조건으로 만들지 않는다.
4. 승인된 작업은 구현·검증까지 이어간다. 질문이 필요하면 이미 결정된 내용인지 먼저
   확인하고 독립적으로 가능한 작업을 계속한다. 범위 축소나 운영 변경 승인을 추정하지 않는다.
5. 같은 PR에 `docs/plan.md`의 현재 위치·상태·결정과 필요한 열린 질문 변경을 반영한다.
   상세 증거는 해당 `workthrough/` 기록 하나에 모으고 계획에는 링크한다. 기존 기록을 재사용한다.

인계에는 `WP/요구사항 → PR/브랜치 → SHA → 실행 결과·제한 → 다음 행동`을 남긴다.
계획·코드·CI·실연결·브라우저·복구·배포를 구분하고, 실제 수용되지 않은 WP나 상위
메인/명세를 `Closes`로 닫지 않는다. GitHub 게시·머지·릴리스는 현재 사용자 요청의 권한을 따른다.
